# 数据表示

## 补码的性质

定点数用补码表示

浮点数用源码表示尾数，阶码越大，说明该浮点数越大。浮点数之间比较时优先比较阶码。
浮点数: (符号位) (阶码) (尾数)  

移码只用于表示浮点数的阶码，希望编码值和真值是线性正比的关系

假设在三位的真值中，取一个相对中间值 "000" 作为真值 0，用于表示阶码

| 移码  | 111 | 110 | 101 | 100 | 011 | 010 | 001 | 000 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 真值  | 3   | 2   | 1   | 0   | -1  | -2  | -3  | -4  |
其中用于表示真值 0 的 100 则可以称为偏移量，那么需要表示的阶乘，即移码值为偏移量+X真值

在计算机中常用移码来表示浮点数的阶码，阶码为整数
机器字长为n位，则移码定义: [X]移=2^(n-1) + X，其中: -2^(n-1)≤X＜2^(n-1)

[X]移码 <--符号位取反--> [X]补码

正数原码反码补码三码合一，移码为符号位取反
补码计算:  负数为由低位向高位数第一个1开始(不包括第一个1)，其余数值位取反，符号位不变，移码为符号位取反
右移运算时: 正数，高位补0，低位舍去。如果是负数，**则高位补符号位，即1**，低位舍去。
左移运算时: 正数，高位舍去，低位补0。如果是负数，则考虑溢出的两个符号位是否相同，同号忽略不计，异号溢出则记入状态位寄存器的溢出位

做题时优先判断手上数的符号位，正数三码合一直接OK，负数须小心。
原码反码分正负零，补码不分正负零，补码总不存在的-0意为-128，原码中符号位不计入数值位，
反码符号位确认为负数再取反为原码时，同符号不变，仅数值位取反，补码的最高位只做符号位，不计入数值。

## 浮点数一般格式

浮点数的规格化表示类似于十进制的科学计数法，
浮点数必须规格化表示以提升精度，
即(**原码下**)浮点数规格化要求尾数最高位必须要为1。
如果符号位与最高位不同，则说明当前浮点数位规格化浮点数。

因为浮点数规格化要求尾数最高位必须要为1，
所以浮点数中无法表示0，但可以存储绝对值接近0的数。
在IEEE754国际标准中有能够表示非规格化存储数字的方式。

浮点数相加时，浮点数尾数相加溢出到小数点前并不代表溢出，只有阶码溢出的时候才是溢出。
以下数据为(**补码**)，**补码尾数最高位为0**。
如尾数出现 11.1x...x 或者 00.0x...x 的形式时，须将尾数左移1位，阶码减1，
直到尾数规格化为止，小数点前仅保留一位符号位，多出的直接舍弃，底位补0，该操作称为左规。
如尾数出现 01.x...x 或者 10.x...x 的形式时，并不一定溢出，先将尾数右移1位，阶码加1，再判断阶码是否溢出，该操作称为右规。

原码下的浮点数依照类似科学计数法的方式规格化即可，而补码下的浮点数则需要连同符号位数值位进行左规或者右规。

浮点数在无IEEE754标准下的规格化范围：
符号位1位，阶码(移码)6位，尾数数值位9位
补码：\[-1, -1/2) ∪ \[1, 1/2)
原码：(-1, -1/2] ∪ \[1, 1/2) ，原码的范围关于0点对称
本例浮点数的表示范围：

| 负上溢                 | 可表示的负数                            | 负下溢                  | 0   | 正下溢                 | 可表示的正数                          | 正上溢                |
| ------------------- | --------------------------------- | -------------------- | --- | ------------------- | ------------------------------- | ------------------ |
| (-∞, -2.1475\*10^9) | \[-2.1475\*10^9, -1.1687\*10^-10] | (-1.1687\*10^-10, 0) | 0   | (0, 1.1642\*10^-10) | \[1.1642\*10^-10, 2.1433\*10^9] | (2.1433\*10^9, +∞) |
**定点数在数轴上均匀分布，而浮点数无论正负在数轴上离零越近表示的浮点数数量越密集，反之越稀疏。**

## IEEE754

IEEE754浮点数格式标准

目的：便于程序从一类处理器一直到另一类处理器上，研制更为复杂的数值运算程序。
规定：
+ 尾数用原码表示，小数点前隐含一个 "1"
+ 基值隐含为2
+ 阶码用移码表示，移码的偏移值有专门约定: n位移码的偏移值为2^(n-1)-1
+ 指数(阶码)的最大值、最小值作为特殊标记预留，用来标记某些异常事件或机器零
+ 单精度、双精度；单精度扩展、双精度扩展

### 移码

float 32 位: S符号1位 **阶码8位** 尾数23位
double 64 位: S符号1位 **阶码11位** 尾数52位

IEEE754的浮点数中，尾数用原码表示，且基值为2，如S1.xxx...xxx，
而小数点前必须有个"1"，那么就没必要再存储了，
因为已经在标准中约定好了，即小数点前隐含一个"1"，
即常规无标准的逻辑下float中23位的尾数在该规则中可以表示24位尾数。

IEEE754标准中，阶码也是用移码来表示的。
且移码的偏移量也并非原先的"**高位第一位为1，其余位全0**"，
而是"**高位第一位为0，其余位全1**"用来表示移码中的"**0**"，即并非相对最终中间两位的高者，而是低者。

以下为8为移码中的全部表示数据范围

| 移码中的数据    | 表示的值 |
| --------- | ---- |
| 1111 1111 |      |
| 1111 1110 |      |
| 1111 1101 |      |
| ......    |      |
| 1000 0001 | 2    |
| 1000 0000 | 1    |
| 0111 1111 | 0    |
| 0111 1110 |      |
| ...       |      |
| 0000 0010 |      |
| 0000 0001 |      |
| 0000 0000 |      |
因为偏移选择中间偏下的，
那么该标准下，正方向表示的数会比负方向多一个，则 8位 下的阶码 表示范围为 128~-127

因为尾数用原码表示，小数点前隐含一个 "1"，**所以无法表示"0"**，
**因此IEEE754把阶码的 全一和全零 取走不再用于表示阶码而是用于做特殊标记，因此在该设计下8位float阶码表示范围又到了127~-126**。

以下内容以 float 32 位演示

**阶码中全零的特殊标记 代表 该浮点数尾数的小数点前没有隐藏的 "1"，
即 S0.xx...xx (float)，此处小数点后xxx共23位，那么此时如果数值23位全为0，
那么在没有小数点前隐藏1的情况下，该数表示的就是0。
而如果在没有小数点前隐藏1的情况下，数值位并非全1，
则代表当前浮点数为非规格化数，即当前尾数可以用非规格化形式表示，
因为此处阶码位为全零，则使用一个默认的值 (0000 0001)-126 来表示非规格化尾数真正的阶码(模数的幂)**

**注意：非规格化数的阶码为全0特殊标记，因此无法正常表示真实阶码，故默认以-128为非规格化数的阶码**

**阶码中全一的特殊标记 代表 正负无穷大，
如 (S 11111111 00...00)，(0 11111111 00...00)==>+∞，(1 11111111 00...00)==>-∞，
在没有IEEE754标准时计算机在得出结果为负上溢和正上溢后无法表示，程序后崩溃中断直接丢失所有的计算信息，
而阶码全一的特殊标记下实现了正负无穷的表示，程序在此时就不会崩溃，系统不会再中断终止该程序。
如 (S 11111111 yy...yy)
在尾数不为全零的情况下，则该数据表示 NaN (not a number 非数)，
比如CPU内部计算开根得出负数或更复杂的运算而无法表示结果，
系统要中断结束程序运算时，如果能表示为非数即可解决该问题保证程序不崩溃继续下一个运算。**

### 非规格化数

为什么要引入非规格化浮点数：
例：规格化浮点数的值 1.xxx \* 2^xxx
那么在IEEE754中移码的全零全一被用于表示特殊情况了，即三位移码表示范围为 -2~+3，-3与+4被保留
x = 1.011 \* 2^(-1)
y = 1.001 \* 2^(-1), x ≠ y, 但
x - y = 0.010 \* 2^(-1) =(左规) 1.000 \* 2^(-3) = 0
此时必须保证 x = y <==> x - y =0，
如: if (x!=y) then z=1/(x-y)，x和y不相等却相减为0，0作为分母程序直接报错。

那么此时采用 **渐进下溢** 的方式处理，
即 x - y = 0.010 \* 2^(-1) =(左规) 1.000 \* 2^(-3) = 0，
左规后阶码为-3，如果阶码为-2，则 x - y = 0.100 \* 2^(-2)，此时就不会再得到0的输出了，且刚好在三位阶码中，-3是一个最低的保留位。

**非规格化数的核心价值**

1. **平滑过渡**：在数值接近0时，允许以逐渐降低精度的方式表示，而非直接归零。
2. **避免逻辑矛盾**：确保 `x ≠ y ⇨ x - y ≠ 0`，防止除以零等异常。
3. **扩展表示范围**：填补规格化数与0之间的数值空白。

### 舍入模式

#### 就近舍入

舍入到最接近的可表示值；当有两个最接近的可表示值时，首选"偶数"值。

|            | 就近舍入模式 | 四舍五入模式 |
| ---------- | ------ | ------ |
| Round(0.5) | 0      | 1      |
| Round(1.5) | 2      | 2      |
| Round(2.5) | 2      | 3      |
| Round(3.5) | 4      | 4      |

| 原始二进制尾数             | 就近舍入之后         |
| ------------------- | -------------- |
| 1.0100110 **10010** | 1.010011 **1** |
| 1.0100110 **01111** | 1.010011 **0** |
| 1.0100110 **10000** | 1.010011 **0** |
| 1.0100111 **10000** | 1.010 **1000** |
二进制"偶数"：只看保留的最后一位是否为 `0`。
- 截断位等于中间值(10...0)：末位为0 → 舍去；末位为1 → 进位。
- 截断位不等于中间值(10...0)：按四舍五入直接处理。

#### 朝0舍入

+ 截尾
+ 使取值的绝对值比原值的绝对值小
+ 容易导致误差积累
例：int(1.234)=1，int(-1.234)=-1

#### 朝+∞舍入

+ 正数: 只要多余位不全为0，则向最低有效位进1
+ 负数: 截尾
例：ceil(1.234)=2，ceil(-1.234)=-1

#### 朝-∞舍入

+ 正数: 结尾
+ 负数: 只要多余位不全为0，则向最低有效位进1
例：floor(1.234)=1, floor(-1.234)=-2

#### 小结

|​**舍入模式**​|​**方向描述**​|​**正数示例**​|​**负数示例**​|​**二进制示例（保留整数位）​**​|
|---|---|---|---|---|
|​**朝零舍入**  <br>(Round toward Zero)|向靠近零的方向舍入（正数向下，负数向上）|`1.9 → 1`  <br>`2.5 → 2`|`-1.9 → -1`  <br>`-2.5 → -2`|`10.1 → 10`  <br>`-10.1 → -10`|
|​**朝正无穷舍入**  <br>(Round toward +∞)|向更大数值方向舍入（正数向上，负数向上）|`1.1 → 2`  <br>`2.5 → 3`|`-1.1 → -1`  <br>`-2.5 → -2`|`10.001 → 11`  <br>`-10.001 → -10`|
|​**朝负无穷舍入**  <br>(Round toward -∞)|向更小数值方向舍入（正数向下，负数向下）|`1.9 → 1`  <br>`2.5 → 2`|`-1.9 → -2`  <br>`-2.5 → -3`|`10.999 → 10`  <br>`-10.999 → -11`|
计算机 ​**遵循预设规则** 选择舍入模式：

- **默认行为**：始终使用 ​**向最近的偶数舍入**，除非程序员或硬件显式指定其他模式。
- **例外情况**：
    1. **溢出/下溢**：当结果超出浮点数表示范围时，自动按标准规则处理（如返回±∞或非规格化数）。
    2. **特殊指令**：通过编程语言或硬件指令手动切换舍入模式（例如C语言中的 `fesetround()`）。

| ​**舍入模式**​   | ​**应用场景**​                |
| ------------ | ------------------------- |
| ​**向零舍入**​   | 游戏物理引擎（快速截断坐标）、金融计算（避免超支） |
| ​**向正无穷舍入**​ | 确定算法的最坏情况上界（如内存分配上限）      |
| ​**向负无穷舍入**​ | 计算资源下限（如最小线程数、任务截止时间）     |
## IEEE754-2008

+ 原IEEE浮点数标准只定义了32位float单精度、64位double双精度浮点数。
+ 2008年的标准新定义了**16位、127位、k位**(k≥128)的标准。
+ 加入了**十进制**浮点数格式：decimal32、decimal64、decimal128、decimal{k} (k≥32)。

标准中新增的十进制浮点数常用于金融领域，因为二进制的小数转换为十进制难免截尾损失精度。

**浮点数精度总结：​**
1. **单精度（float）​**：
    - 24位有效尾数 ≈ ​**7位十进制有效数字**​（非小数点后7位）。
2. **双精度（double）​**：
    - 53位有效尾数 ≈ ​**16位十进制有效数字**。
3. **关键公式**：
    - 十进制有效位数 = 二进制位数 × log₁₀(2) ≈ 二进制位数 × 0.3010。
4. **误差特性**：
    - **相对精度**，误差随数值大小变化，整数部分占用越多，小数部分精度越低。
5. **编程注意**：
    - 避免直接比较浮点数，用容差（如 `abs(a-b) < 1e-6`）。
    **一句话**：浮点数精度看有效位数，非固定小数位，误差相对且随数值缩放。

## 编码表示

**计算机中定点数常用补码表示，浮点数的尾数用原码表示，浮点数的阶码用移码表示。**
### ASCII码

American Standard Code for Information Interchange(美国国家信息交换标准代码)
**字符与二进制编码的对照标准，用于计算机和通信设备。
ASCII码是7位的码来表示字符。7位二进制 → ​共128种组合( 0x00~0x7F )。**

ASCII码的第8位一般用作网络传输的 **奇偶校验位**，
而非数值存储，因此**数值位仅7位**。
网络传输完成后奇偶校验完成就舍去该位，保留后七位，再给最高位补0。

|---|---|---|---|
|​**控制字符**​|33个|0x00~0x1F（如换行、回车、退格）|`0x0A`（换行）|
|​**数字 0~9**​|10个|起始值 `0x30` + 数字值|`0x30`→'0', `0x39`→'9'|

|​**小写字母 a~z**​|26个|起始值 `0x60` + 字母顺序号（a=1→0x61）|`0x61`→'a', `0x7A`→'z'|

    - 大写字母范围：`0x41`（A）~`0x5A`（Z）。
    - 小写字母范围：`0x61`（a）~`0x7A`（z）。
2. **大小写转换**：
    - 大写与小写ASCII码相差 `0x20`（如'A'=0x41，'a'=0x61）。
3. **特殊字符分布**：
    - 常见符号：`! " # $ % & ' ( ) * + , - . /` 等。

- **数字**：`'0'` 的ASCII码是 `0x30`，依次递增。
- **字母**：
    - 大写字母 `A` → `0x41`（A是第1个字母，`0x40+1=0x41`）。

### 数据错误类型

#### **1. 突发性错误（Burst Error）​**

- **定义**：多个连续比特位发生错误（如一次干扰导致连续多个位出错）。
- **本质**：
    - **集中性**：错误集中在某一时间段或物理区域（如磁盘坏道、电缆损坏、突发电磁脉冲）。
    - **关联性**：前后错误**高度相关**​（如信道干扰导致连续10位数据全被破坏）。
- **典型场景**：
    - 物理介质损坏（如光盘划痕、硬盘磁头故障）
    - 信道瞬时干扰（如雷电、电源波动）

---

#### **2. 随机性错误（Random Error）​**

- **定义**：单个或少量比特位随机、分散地发生错误（彼此无关联）。
- **本质**：
    - **分散性**：错误位置**无规律**，彼此**独立**​（如宇宙射线随机翻转内存某一位）。
    - **均匀概率**：每个比特位出错的可能性相同。
- **典型场景**：
    - 电磁噪声干扰（如无线通信中的热噪声）
    - 硬件老化导致的偶发位翻转

---

#### **核心区别总结**

|​**特征**​|突发性错误|随机性错误|
|---|---|---|
|​**错误分布**​|连续、集中|分散、独立|
|​**关联性**​|错误之间有物理/时间关联|无关联|
|​**纠错难度**​|更难（需专门编码技术*）|较易（如海明码可纠正）|
|​**典型应对方法**|交织编码（分散突发错误）|奇偶校验、海明码|

**注**：突发性错误常用**交织技术（Interleaving）​**​ 将连续错误分散成随机错误，再结合纠错码处理。

### 检错纠错

#### 奇偶校验码

##### **原理**​

- **目的**：检测单比特错误（奇数个错误）。
- **规则**：在数据末尾添加1位校验位，使整个数据中“1”的个数为奇数（奇校验）或偶数（偶校验）。
- **只能检错，不能纠错**​（除非明确知道错误位置）。
##### **例子 & 计算**​

**数据：`1011001`**​（7位数据）

- **奇校验**：  
    数据中“1”的个数 = 4（偶数），校验位填1 → ​**`1011001`**`1`（总共有5个“1”，奇数）。
- **偶校验**：  
    校验位填0 → ​**`1011001`**`0`（总共有4个“1”，偶数）。

**检错场景**：

- 如果接收到的数据是 `10110011`（奇校验），但实际“1”的个数变为偶数（如传输中某位翻转），说明发生错误。

#### 循环冗余校验码

Cyclic Redundancy Check，检错CRC。
##### **原理**​

- **目的**：检测多位错误（如突发错误）。
- **核心**：用多项式除法生成校验码，发送方和接收方约定同一个生成多项式（如 `CRC-8`、`CRC-32`）。
- **只能检错，不能纠错**​（但检错能力远强于奇偶校验）。

##### 计算步骤

(以CRC-4为例)

**生成多项式**：`x³ + x + 1` → 二进制 `1011`（4位）。  
**原始数据**：`110101101` → 二进制长度为9位。

1. **补0**：在数据末尾补 `生成多项式位数-1` 个0 → `110101101` + `000` = `110101101000`。
2. **模2除法**：用补0后的数据除以生成多项式（按位异或，无借位）。
    ```
         110101101000  
         ÷     1011  
         ————————————  
         余数：010  → 校验码
    ```
3. **发送数据**：原始数据 + 余数 → `110101101`**`010`**。

**检错场景**：

- 接收方用同样的生成多项式去除接收到的数据，若余数 ≠ 0，说明传输有误。
- 因为原始数据已经和校验码相除，即减去了模2除法的余数，在原始数据失去余数的情况下再与生成多项式相除校验是可以除尽的，以此为检测手段。

**循环冗余校验码可以检测所有低于16位的突发性错误，大于16位的突发性错误，检测出的概率为99.99%。但随机性错误无法检测，故而又有了海明码。**
### 海明码

海明码 (Hamming code) 由 Richard Hamming 于 1950 年提出。
+ 主要用于**存储器**数据的**校验**与**纠正**。
+ 采用奇偶校验的原理，错误检测和矫正能力随着信息中加入奇偶校验位的数目线性增加。
+ 适用于最有可能发生随机错误的系统。
  - 每一位出错的**概率**相同；
  - 每一位与其他位是否出错没有任何**关联**。
  随机性错误适合使用海明码进行**校验**和**纠错**，且**海明码是基于奇偶校验码的，海明码编码位从1开始。**。

#### 检错纠错方法

编码字有n位，其中有信息码m位和校验码r位。 n = m + r。
r位校验码可以区分出："1个合法的编码字 + n个非法的编码字" ==> **2^r ≥ (m+r+1)**

| 编码字：   | n位     |
| ------ | ------ |
| 信息码：m位 | 校验码：r位 |

#### 核心公式

**2^r ≥ (m+r+1)** 这个公式相当重要，要记住。

##### **1. 校验码的核心作用**

- **校验码（r位）​**​ 的任务是生成一个**错误定位码（校验子）​**，用于判断：
    - **是否出错**​（合法编码字 vs 非法编码字）
    - **哪里出错**​（定位错误的具体位置）
##### **2. 校验子的覆盖范围**

- **校验子（Syndrome）​**​ 是校验码计算出的结果，用 ​**r位二进制数**​ 表示，因此共有 ​**2ʳ种可能值**。
- 这些值需要覆盖以下所有情况：
    - **1种合法情况**：无错误（校验子全为0）。
    - **n种非法情况**：每个比特位单独出错（总共有 ​**n = m + r**​ 位，每位可能出错）。
    - **总计需区分的情况数**：`n + 1`（1个合法 + n个非法）。
##### **3. 公式推导**

校验子的可能值必须 ​**≥ 需要区分的总情况数**，即：

2r≥(n+1)其中n=m+r

代入得：

2r≥(m+r+1)
##### **4. 直观理解**

- **校验码的本质**：用 ​**r位二进制数**​ 为每个可能的错误位置（包括无错误）分配唯一标识。
- **例子**：若校验码有3位（r=3），则校验子有8种值（2³=8），最多可覆盖7种错误位置（需满足 `8 ≥ m + 3 + 1` → `m ≤ 4`，即最多4位信息码）。
##### **5. 边界条件**

- **纠错能力上限**：当 `2^r = m + r + 1` 时，r位校验码刚好覆盖所有可能错误位置。
- **若不等**：当 `2^r > m + r + 1` 时，校验码有冗余（可检测更多错误，但无法纠正）。

#### 最小海明距离

**最小海明距离（d）​**：任意两个合法编码字之间不同的最小位数。最小海明距离为3。

因为一个数值的位号一定是由两个2的正数次幂相加来纠错的，
因此如果要把存在一个错误数值的数据要更改为合法的，那么起码要修改两个奇偶校验位。
任何两个合法的编码字之间至少有三个字是不一样的，所以最小海明距离是3。

在此基础上，如果传输数值中出现两个错误，
那么在海明距离内是不会变成"合法的错误数值"。所以如果三位数值出错则无法保证差错纠错的处理。

#### 双符号位判决法

比如两个n位补码相加，如果发生溢出，
那么n+1位一定能存储运算结果。
即多于n位的双符号位不同，即相异，那么则说明发生溢出。

双符号位：
+ 00: 不溢出，结果为正
+ 11: 不溢出，结果为负
+ 10: 溢出，负溢
+ 01: 溢出，正溢

#### 进位判决法

  0 1000001 ···65
+0 1000011 ···67
  1  0000100 ···超出127溢出

如果最高位数值向更高位的符号位进位时，
和 符号位向更高位进位的 进位值相异 的话，表明溢出。
反之，代表运算过程中没有发生溢出。

在CPU中，进行定点数运算是否发生溢出，

#### BCD数加法器

##### BCD加法的校正

运算中某位BCD数(四位二进制数) **相加的结果大于9 或 有向更高位的进位** ，则结果加6。如不满足条件，则无需校正。

因为BCD是用二进制编码来表示十进制数据，只表示 0-9 十个数，
如果计算值超出9的话，那么没有专门的BCD码值专门表示十位以上的数。

因此BCD码相加的时候，发生进位或者数值大于9时就需要校正结果，用0-9的BCD码来表示出大于9的值。

![](./COA/Pasted_image_20250303211551.png)

##### 数学原理

1. **进制差异补偿**​
   
    - 四位二进制进位阈值为16（2^4）
    - 十进制进位阈值为10  
        差额为 16−10=6，加6补偿该差异。
2. **修正公式**​  
    若结果 S=A+B 满足 S>9 或进位 C=1：
    
    S修正​=S+6=(S−10)+16
    
    其中：
    
    - S−10 为正确的个位值
    - +16 触发二进制进位，对应十进制十位的1

### 除法运算

除法本质即若干次减法，商为减到几次时被减(除)数不够减或为0

+ 定点纯整数时，|被除数| < |除数|

##### 恢复余数法

**基于补码的除法运算**。

除法本质即若干次减法，商为减到几次时被减(除)数不够减或为0。
恢复余数法即不停的做减法，按位减完之后判断每次结果的正负，
根据正负来判断够不够减数决定商1或商0，
因为只能先减去判断结果正负才能知道够不够减，
因此不够的时候需要把减去的数加回来，即恢复到上一步的值并商0，谓之恢复余数法。

![](./COA/Pasted_image_20250305212411.png)

注意：加上 -|Y| 的值得出结果后，确认符号位是否为正数，
如果是正数则说明够减，否则说明不够减。
以**每轮计算结果的正负双符号位作为是否够减的标准**，而非用除数与计算值中前一半位进行比较。

## 浮点运算

浮点数运算时，尾数溢出不代表溢出，只有阶码溢出才算做溢出。

### 加减运算

设两个浮点数：X=M(x) \* 2^(Ex), Y=M(y) \* 2^(Ey)
用M(x)、M(y)分别表示x、y的尾数、Ex、Ey分别表示x、y的阶码

实现对 X ± Y 运算的法则

#### 计算方法

##### 对阶

浮点数计算时需要在阶码一致的情况下才能进行计算，
因此**第一步为对阶**，
对阶时，小的阶码向大的阶码对齐。
小阶码+1，尾数右移1位，直到增大到与大阶码相同。

##### 尾数运算

尾数加(减)运算
加法；(正数三码合一，无需求补)
减法：减数的符号取反(求补)，与被减数相加。

##### 规格化

规格化：1、左规 2、右规

左规
运算结果尾数为：
+ 11.1xx...x 或 00.0xx...x：尾数每**左**移1位，阶码**减1**，直到使尾数称为规格化数为止。
+ 阶码减1，必须同时判断是否**下溢**。若发生下溢，可认为结果为0。

右规
若结果(尾数)发生溢出，即结果出现 10.xx...x 或 01.xx...x 时，
+ 尾数**右**移1位，阶码**加**1。右规最多1次。
+ 阶码加1，必须同时判断是否**上溢**。若发生上溢，可认为结果为∞。

##### 舍入处理

+ 截(尾)断法：将需要丢弃的尾数低位丢弃。
+ 末尾恒置1法：使要保留的尾数的最低位永远为1。(优点：误差积累小 / 缺点：损失一位精度)
+ 0舍1入法：
  + 当尾数右移丢弃的是**1**时，要保留的尾数最末尾**加1**；
  + 当尾数右移丢弃的是**0**时，要保留的尾数最末尾**不变**。
  + 当遇到01.111...11这种需右规的尾数时，采用此法会再次使尾数溢出。遇到这种情况可采用**截尾法**。

# 存储系统

本章节主要以半导体存储器为核心，即以芯片形式存在的存储器。

两个或两个以上速度、容量和价格各不相同的存储器用硬件、软件、或软件与硬件相结合的方法连接起来成为一个存储系统。
这个存储系统对应用程序员是透明的，并且，从应用程序员看，它是一个存储器，
这个存储器的速度接近速度最快的那个存储器，存储容量与容量最大的那个存储器相等，单位容量的价格接近最便宜的那个存储器。

## 简单计算机系统

![](./COA/Pasted_image_20250311235723.png)

计算机各个部件通过总线进行互联，CPU外部引脚很多，因此还需要一个总线形成电路才能组建起完整的系统总线。
而其他计算机外设因为各种电压电频都不一样，无法直接连接到标准的系统总线上，因此外设需要一个 **接口** 中转连接到总线上。

### 基本计算机启动流程

CPU开始工作就是从内存里取指令，但是内(主)存(RAM)通电时里面的电平数据是随机无序的，因此必然不能作为指令被CPU读取。
所以CPU的指令首先是从 主板上的 ROM (非易失性存储器，即掉电时数据不丢失) 读取，即 BIOS 系统。
CPU 从 ROM 里的 BIOS系统 取到指令开始执行，首先 BIOS系统命令 先进行硬件自检，如CPU主存磁盘风扇等等。
接着 BIOS 初始化各种外设的接口，这些智能化的可编程接口也是存在寄存器的，但是这些寄存器在刚通电时是没有值的，
所以 BIOS 需要向这些接口的寄存器中写入预先设定的值，以确保外设能够正常工作，即 BIOS 硬件自检后，初始化了外设接口才能访问外设。
此时 BIOS 才能正常访问磁盘，再访问磁盘中的引导扇区的代码，将 **引导扇区代码** 通过CPU中转入内存中，此时 BIOS系统 任务完成。

此时CPU读取主存中引导扇区代码，解析磁盘数据结构，
如磁盘有多少分区，存储设备上有没有引导签名(确认是否存在操作系统)，
如果有引导签名，那么开始定位系统引导分区，将系统引导程序再次载入内存。

CPU执行内存中的系统引导程序，开始将操作系统所需的各个程序向内存中加载，启动并进入系统环境。

### 存储器

整个计算机启动过程中出现了很多存储器，如磁盘、RAM、ROM、Cache、寄存器。
但是CPU的速度一般是主存速度的百倍以上，因为其他存储器的速度不高，CPU速度再快也不好协调。
因此人们又做了CPU内部的高速缓存Cache，存储比寄存器大，但是速度比寄存器低，比主存快，用于存储频繁调用的数据。

存储器的速度从快到慢：寄存器 > Cache > 主存 > ROM > 磁盘

为了协调各个存储器之间的速度，让其能组合在一起工作，采用软硬件结合的方式来管理存储器。
存储体系分三级：
+ Cache与主存之间称为 Cache 存储体系：CPU内部纯硬件管理
+ RAM与磁盘之间称为 虚拟 存储体系：软(系统)硬件结合管理

###### 全相联

适用于小容量的Cache，如果容量一大则电路实现过于复杂从而导致速度变慢。

映射规则：
**主存的任意一块可以映象到Cache中的任意一块。**

+ 块冲突概率低，Cache空间利用率高
+ 相联目录表容量大 → 成本高、查表速度慢

###### 直接映射

**主存是按照Cache的容量分区的**

映射规则：
**主存的每一块只能映象到Cache的一个特定的块中。**
整个Cache地址与主存地址的低位部分完全相同。

优点：
+ 硬件简单，不需要相联存储器，只要
  容量较小的按地址访问的区号标志表存储器
  少量外比较电路
+ 访问速度快(无需地址变换)
缺点：
+ Cache块冲突概率高
+ Cache空间利用率很低

![](./COA/Pasted_image_20250316000812.png)

此时区号比较则无需相联多路比较器，一个相等比较器即可。
主存是按照Cache的容量分区的，而区内的块号是与Cache的块号规则是一致的，
因此比较完区号之后直接用Cache的块号+块内地址直接访问主存即可，即**舍去区号剩下的就是Cache地址**。

但是直接映射限制比较大，不灵活，比如某个区的第三块，那么只能装到Cache的第三块。

###### 组相联

组相联是全相联和直接映射的**折中**。
即主存的组与Cache的组直接映射，而组内全相联，可以装入Cache对应组内的任意位置。

![](./COA/Pasted_image_20250316170205.png)

以图中地址为例，主存地址除以256(即2^8)就得到了区号，即相当于主存地址右移八位，可以保留在小数点前的只有区号。

![](./COA/Pasted_image_20250316171149.png)

优点：
+ 块的冲突概率比较低；
+ 块的利用率大幅度提高；
+ 块的失效率明显降低。
缺点：实现难度和造价比直接映射方式高。

###### LRU

![](./COA/Pasted_image_20250317191631.png)

此图以四块为例，因此标志位仅需2bit，
有空位装入新的块时，当前块的status位置00，其他位+1；

如果命中了某一块，那么当前位置0，**小于当前位的+1，大于当前位的不变**。

新入的和新替换的放于最顶，最久不用的栈底，因此LRU算法也称堆栈算法。

###### 写回法

+ Cache命中，则CPU直接存取或改写Cache中的最新数据，
  **提高读写速度，但是这意味着主存对应的数据没有得到实时更新，可能是过时的旧数据。**
+ Cahe中该块需替换时，则将当前Cache块中的最新数据直接写回到主存中，更新主存的过时信息。
+ Cache不命中时，将该主存中该块直接拷贝到Cache中。

###### 全写法

写直达法

+ Cache命中时，CPU直接读写Cache中的数据，但是写的时候同时要把最新的数据写入内存，**这意味着速度的损失，但是主存不会出现旧数据的情况**。
+ Cache不命中则直接对主存中的数据进行读写
  -- WTWA法(写分配法)：取主存块到Cache
  -- WTNWA法(写不分配法)：不取主存块到Cache
+ Cache、主存一致性好；速度慢。

###### 两种写法对比

全写法兼顾Cache与主存的一致性，但是会拖慢CPU速度。

写回法速度快，但是存在主存与Cache的数据一致性问题，即主存的数据可能比Cache落后，
如果此时DMA直接来访问内存，那么DMA搬走的旧数据被拿去使用可能会出现一些问题。

###### 情景分析

![](./COA/Pasted_image_20250317213842.png)

4号是单核处理，直接写回法最快速度解决即可，
而且没有其他IO设备(如DMA)读取内存，不存在数据一致性问题。

1号多了IO设备，在总线上可以对主存进行读写，此时Cache的数据是最新的，
内存数据落后出现数据一致性问题，那么IO搬走主存上的旧数据就会出现问题。

2号的IO设备在总线上仅对主存进行写入数据，
那么此时Cache的数据相对主存来说又是旧数据了，而主存内是最新的数据。

3号是多核多处理器情况。**每个CPU有自己私有的一二级缓存，共有的三级缓存**。
如果一个CPU的Cache中发生了修改变成了最新的数据，而另一个CPU的Cache中也是对应同一内存块，
那么第一个CPU更新最新Cache的时候会在总线上发出信号，另一个CPU的Cache直接做废自己当前的旧数据Cache块，
假设某个CPU未命中Cache需要读取主存时，首先在总线发出信号，
如果其他CPU的Cache有对应主存块的最新数据，则直接由其他CPU的Cache中的最新数据向对方提供，而不是访问主存。

## 虚拟存储器

现代操作系统多用页式虚拟存储器，因为段页式太复杂了。

段表页表创建由操作系统管理，地址转换由MMU(Memery Management Unit)完成。

虚拟存储器工作大部分由软件(操作系统)实现。
因为高速**主存容量**满足不了需求，所以设计了虚拟存储器。
多道程序运行 --> 各程序独立编址 --> 程序再定位 --> "逻辑地址 --> 实际地址"

![](./COA/Pasted_image_20250318173447.png)

其中CPU内包含的MMU(储存管理单元)为虚拟存储器的辅助硬件，同时它也帮助实现逻辑地址的转换。

虚拟存储器中有三种地址空间：
- 虚拟地址空间(逻辑地址)：程序员编程中用到的地址。 ==> 编译程序生成
- 主存储器地址空间(常用数据以页的形式存在主存中)：实际主存的物理地址。 ==> CPU地址引脚
- 辅存地址空间(不常用数据的页常常存在磁盘中)：磁盘存储器的地址。

地址映象(LRU)：
把虚拟地址空间映像到主存地址空间。(虚拟存储器地址映象就是全相联)
即把用户按虚拟地址编写的程序按照某种规则装入主存储器，并建立多用户虚地址与主存实地址之间的关系。

地址变换(MMU)：
在程序运行时，把虚地址变换成主存实地址。

### 磁盘阵列RAID

![](./COA/Pasted_image_20250320170955.png)

#### **RAID 0（条带化）​**

- **原理**：数据分块（条带）存储在多个磁盘上，无冗余。
- **特点**：
    - 提高 ​**读写性能**​（并行操作）。
    - **无冗余**，单盘故障导致数据丢失。
- **优点**：
    - 最高性价比，适合对性能要求高的场景。
- **缺点**：
    - 数据可靠性差。
- **适用场景**：临时数据、缓存、非关键任务。

---

#### **RAID 1（镜像）​**

- **原理**：数据完全复制到多个磁盘（镜像）。
- **特点**：
    - 提供 ​**冗余**，单盘故障不影响数据。
    - 写入性能略降（需写两份数据），读取性能提升。
- **优点**：
    - 数据安全，适合对可靠性要求高的场景。
- **缺点**：
    - 存储效率低（50%冗余）。
- **适用场景**：财务数据、日志文件、操作系统盘。

---

#### **RAID 2（汉明码校验）​**

- **原理**：数据分块存储，额外位用于汉明码纠错。
- **特点**：
    - 理论上支持单比特错误纠正。
- **现状**：
    - 实现复杂，已被淘汰。

---

#### **RAID 3（专用奇偶校验盘）​**

- **原理**：数据条带化存储，单独磁盘存储奇偶校验位。
- **特点**：
    - 适合 ​**顺序读写**，单盘故障可恢复。
- **缺点**：
    - 校验盘成为瓶颈，写入性能差。
- **现状**：
    - 实际应用少。

---

#### **RAID 4（独立奇偶校验盘）​**

- **原理**：与RAID 3类似，但以块为单位存储奇偶校验。
- **特点**：
    - 支持并行读取，但写入需更新校验块，性能瓶颈仍在校验盘。
- **现状**：
    - 较少使用。

---

#### **RAID 5（分布式奇偶校验）​**

- **原理**：数据条带化存储，奇偶校验块分布到所有磁盘。
- **特点**：
    - 单盘故障可恢复，读写性能较好。
    - 写入需计算校验块（写惩罚）。
- **优点**：
    - 存储效率高（单盘冗余），成本适中。
- **缺点**：
    - 多盘同时故障会导致数据丢失。
- **适用场景**：文件服务器、数据库。

---

#### **RAID 6（双奇偶校验）​**

- **原理**：在RAID 5基础上增加第二个独立奇偶校验块。
- **特点**：
    - 支持 ​**双盘故障** 恢复。
- **优点**：
    - 数据安全性更高。
- **缺点**：
    - 写惩罚更大，性能略低于RAID 5。
- **适用场景**：对数据安全要求极高的场景（如金融系统）。

---

#### **RAID 01（镜像条带化）​**

- **原理**：先做RAID 0条带化，再对条带组做RAID 1镜像。
- **特点**：
    - 需要 ​**偶数块磁盘**。
    - 提供冗余和性能平衡。
- **优点**：
    - 读写性能接近RAID 0，单盘故障不影响整体。
- **缺点**：
    - 存储效率低（50%冗余）。
- **适用场景**：高性能且需要冗余的场景。

---

#### **RAID 10（条带化镜像）​**

- **原理**：先做RAID 1镜像，再对镜像组做RAID 0条带化。
- **特点**：
    - 需要 ​**偶数块磁盘**。
    - 高性能 + 高冗余。
- **优点**：
    - 读写性能优异，单盘故障不影响整体（除非镜像组全坏）。
- **缺点**：
    - 存储效率低（50%冗余）。
- **适用场景**：数据库、虚拟化环境、高性能计算。

---

#### **对比总结**

|RAID级别|冗余方式|最低磁盘数|容错能力|性能特点|存储效率|适用场景|
|---|---|---|---|---|---|---|
|RAID 0|无|2|无|读写最快|100%|临时数据、缓存|
|RAID 1|镜像|2|单盘故障|读快，写略慢|50%|关键数据、操作系统|
|RAID 5|分布式奇偶校验|3|单盘故障|读快，写有惩罚|~80%|文件服务器、数据库|
|RAID 6|双奇偶校验|4|双盘故障|读快，写惩罚更大|~75%|高安全性场景（金融等）|
|RAID 01|镜像+条带|4|单盘故障（镜像组）|读写接近RAID 0|50%|高性能+冗余|
|RAID 10|镜像+条带|4|单盘（镜像组全坏）|读写最快|50%|数据库、虚拟化、高性能计算|

---

#### **关键点**

1. **RAID 0**：无冗余，性能最强，但风险最高。
2. **RAID 1**：简单镜像，安全但成本高。
3. **RAID 5/6**：平衡性能与冗余，适合大规模存储。
4. **RAID 10**：性能与冗余的最佳组合，但成本高。

## MESI

MESI指Cache的四种状态：修改态、独占态、共享态、无效态。
Cache共享态时，CPU写主存命中Cache，则使用全写法(写直达法)，修改Cache同时也修改主存。
Cache独占态或修改态时，CPU写主存命中Cache，则使用写回法，只修改Cache不修改主存，只有Cache被替换时才一次性写回主存。

每个内核各个Cache通信需要一个互相连接的总线，用于传递Cache一致性协议的消息。

![](./COA/Pasted_image_20250320203718.png)

### Example
#### Step1

![](./COA/Pasted_image_20250320211136.png)

CPU0首先访问自己Cache的x地址数据发现没有命中，通过地址总线访问内存，
将内存中的数据通过数据总线写入到Cache中，
整个读写访问x地址数据的过程中，Share总线没有任何其他CPU的Cache中传来的信号，
则说明当前x地址数据其他CPU的Cache没有，因此由Shared为Cache的状态位写入 Exclusive(独占)。

#### Step2

![](./COA/Pasted_image_20250320212347.png)

CPU1访问x地址数据没有在自身Cache命中故而转向内存，
通过地址线访问到内存的数据后，
把内存的数据通过数据总线写入到自身的Cache中。

在高性能微处理器中，
CPU1未命中Cache**在**通过地址总线访问内存时，
CPU0也在监听地址总线，发现自身的Cache中有CPU1需要的数据，
于是CPU0将自身的状态位E独占修改为Shared共享，并通过Shared共享线通知其他CPU的Cache，
此时CPU1通过Shared线获取到CPU0的Cache中的x地址数据，CPU1也修改自己该数据块状态位为S共享态。

#### Step3

![](./COA/Pasted_image_20250320212827.png)

CPU0要修改x地址数据为4，通过写直达法直接修改Cache，再修改主存，置状态位为E独占。
其他CPU的Cache通过监听地址总线得到x地址数据的修改信号，
CPU1将Cache1中x地址数据的状态位置为Invalid无效，等下次未命中时再次从内存中写回即可。

#### Step4

![](./COA/Pasted_image_20250320213257.png)

CPU0 Cache0命中x地址数据时，发现其状态位为E独占，
那么直接采用写回法，直接只对Cache0数据进行修改为5，状态位修改为M已修改，
即Cache0与主存有数据不一致问题，Cache0的数据是最新的，其他CPU的Cache需要时会由Cache0监听总线提供最新数据。

#### Step5

## 虚存与Cache的协同工作

Intel与AMD处理器工作在64位模式下，系统默认所有段(包括代码段、数据段、堆栈段、附加段)的起始地址都是0，即所谓的平坦内存模型(flat)。
程序中使用的逻辑地址就是线性地址，直接参与分页，相当于不分段、只分页。程序中，即编译器中使用的地址都是从0开始的，称之为逻辑地址或虚拟地址。
当操作系统把程序装载进内存后，通过页式虚拟存储管理机制建立虚拟地址到主存物理地址之间的对应关系。

### AMD皓龙

以AMD皓龙处理器为例，48位虚拟地址，40位物理地址，40位物理地址的主存最大寻址空间为1TB(2^40)。
页式虚拟存储管理采用多级页表的管理形式。

![](./COA/Pasted_image_20250322135847.png)

#### 多级页表划分

**页表级数 = 虚页号位数 / ​每级索引位数**

页表级数 = (48 - 12) / log₂(512)
4k字节为1页，所以页内偏移是12位(2^12)，
虚地址总48位，那么48-12得到虚页号位数为36位。
**每页存储的页表项数** = 页大小（4KB） / PTE 大小（8B） = 512 项。
即 一个 页表 最多可以有 512 个页表项。
**索引位数** = log₂(512) = 9 位
计算结果为 36 / 9 = 4，即四级页表。

如图中所示的虚拟地址，其中页号36位被分为4部分的9位页表项，以最高位的页表项表示位作为最高级页表。
一级别页表在内存中的存储位置必须由操作系统建立起来，再由CPU内部的寄存器CR3(Control Register 3)初始化页表初始地址。

因为最大物理寻址空间为40位，
当查到四级页表中的实页(物理内存)地址为28位，
页内偏移位12位，加起来正好40位物理地址。(参考上图虚拟地址)


#### 页表与TLB

主存访问速度本来就慢，在查询多级页表时因为虚拟地址的关系对速度的影响更大，
为了解决速度问题，会在CPU内部集成一个高速缓存，该缓存中记录的是经常使用的实页号与虚页号之间的地址关系，
该高速缓存可以采用组相联、全相联的地址映射方式，该缓存称之为 **TLB**(Translation Lookaside Buffer，块表 / 转换旁路缓冲区)。

既然存在 TLB 缓存，那么它同Cache一样，在CPU对页表进行操作时仍然会出现数据一致性问题。
因此在修改页表的时候应该清除TLB之中的内容，来确保 内存中页表 与 TLB缓存的 数据一致性问题，

flush(清除) TLB：
```assembly
MOV RAX, CR3 ;CR3寄存器存的是一级页表在内存中的位置
MOV CR3, RAX
```

Control Register 3 (控制寄存器 3)
CR3 是 x86 架构中的一个特殊寄存器，用于存储 ​**页目录表（Page Directory Table, PML4）​** 在物理内存中的基地址。

以上两条指令从逻辑上无法讲通，CR3从结果上来讲数据根本没变。
**但实际上硬件设计CR3寄存器数据如果出现重新写入，那么TLB管理硬件会清空TLB中的全部数据。**
因此修改页表表项时，就需要类似以上的汇编指令对CR3寄存器进行类似的写入操作，触发硬件规则。

##### 进程切换

高性能处理器可以同时运行多个任务，任务会来回切换，但是不同任务使用的虚拟地址都是从0开始编排，
即不同的程序CPU看到的虚拟地址都是一样的，但最终给不同进程分配的物理地址是不一样的，
所以这些程序在页内的虚页号实页号地址对应关系是完全不同的，因此每次进程切换时，每次需要清空TLB，
这样每次切换进程的时候，CPU访问就不会命中TLB，就必须要查询四级页表才能得到最新程序的地址，
也会同时将对应关系装入TLB中，下次再次访问时直接命中TLB就不再去内存四级页表中进行查询了。

##### ASID

进程切换对于操作系统来说是相当频繁的，每次都需要清除TLB内容，因此其中的性能损失也是极其庞大的。
因此在TLB中设计了ASID，用来表示对应进程的TLB表项，从而在切换进程时不会每次都要清除TLB表，
但是所谓的进程号ASID需要由操作系统的软件进行管理和分配，通常情况下进程的ID号取值范围很大，
但是与TLB有关的ASID一般只有8位或者16位，因此操作系统每次创建一个新的进程的时候都要分配新的ASID，
**当ASID分配完之后清空整个TLB表，重新分配ASID号。ASID(Address Space Identifier，地址空间标识符)**。

# 指令系统

硬件搭台，软件唱戏，硬件是根基，指令系统是根基上的舞台，
软件通过指令系统向硬件传递操作内容，类似于翻译器。

指令系统是软件与硬件分界面的一个主要标志；
指令系统是软件与硬件之间互相沟通的桥梁；
指令系统与软件之间的语义差距越来越大；
指令系统的设计主要包括指令的功能(操作类型、具体操作内容)和指令格式的设计。

指令系统：
完备性：指令齐全、编程方便
高效性：占主存空间小，运行速度快
规整性：指令格式尽可能简单
兼容性：向后兼容，即系列计算机以前的功能都要保留

#### 两种间接寻址

基址寻址和变址寻址本质上是同一种寻址方式，但是二者因为使用场合的不同，
基础寻址方式用于实现**主存分段**，段的起始地址可以放在基址寄存器，

#### PC相对寻址

**PC(Program Counter)**: 存储下一条待执行指令的**内存地址**，与代码段寄存器 (如x86的`CS`) 结合形成物理地址。

PC相对寻址不是为了从主存中取操作数，而是为了跳转。
该指令执行时会修改 CPU内部的 PC(程序计数器)寄存器 的内容，
该内容为内存地址，指向下一条要从主存中取出的指令，
如果修改了 PC寄存器 的内容，那么也就是修改了下一条要取的指令在主存的位置，从而实现跳转。

PC相对寻址时，将当前 PC寄存器 与 地址偏移(补码) 相加，结果再次存到 PC寄存器 中，实现修改，达成跳转。

条件转移指令，循环控制指令，子程序调用指令等的寻址方式都是PC相对寻址。

### 操作码设计

定长操作码设计简单，而变长操作码更为灵活且一般采用霍夫码编码方式。

#### 指令长度设计

指令长度与机器字长无固定关系。
一般原则：
- 指令长度为存储器最小可寻址单位的整数倍: CISC (x86)，即必须是字节的整数倍。
- 指令长度一般设计为 **总线宽度** 的整数倍：RISC，比如CPU一次读32位，而指令长度也设计为32位，显然可以提高指令获取速度。
常用设计方案：
- 变长操作码，边长指令码: CISC (x86)
- 定长操作码，定长指令码: RISC
  MIPS，6位定长操作码，32位定长指令码
  RISC-V，7位定长操作码，32位定长操作码

后续的集中操作码设计都遵循着：**短码不能是长码的前缀。** 这一原则，下文中有详细解释。

##### 变长操作码

![](./COA/Pasted_image_20250324152310.png)

固定长度的指令空间有限。操作码长了，地址码就短了；操作码短了，地址码就长了。
而霍夫曼编码中的依据指令使用频度决定长短中，
需要注意：短操作码不能与长操作码前面一部分相同，否则会产生歧义，
计算机会把长操作码前面的一部分作为短操作码解析，长操作码剩下的一部分只能作为地址码解析。
**故而，短操作码不能与长操作码前面的部分相同，即：短码不能是长码的前缀。**

###### 霍夫曼编码

将14条指令依照使用频度进行排序，从高到低作为一个集合。
将集合中数值最小的两位合并作为一个节点，合并后将合并前的两个数从数组移出。
重复之前的操作，直到该集合剩下唯一一个节点，即1.00，所有指令使用频率到达1。

###### 编码特征总结

Huffman编码不唯一：0、1对换；合并次序
只要采用Huffuman编码，操作码的平均码长肯定是唯一的。

在特征码长度种类过多的情况下，硬件实现会有难度。故而又产生了新的操作码类型：**扩展操作码**。

##### 扩展操作码

扩展操作码规定只能有两种码长。
因为所有操作码设计都遵循着 **短码不能是长码的前缀** 这一原则，
因此扩展操作码从短码开始设计。

![](./COA/Pasted_image_20250324162503.png)

其中使用概率大于10%的指令有6条，I1-I6，剩下的都是小于10%使用概率的指令，共8条。
从短码开始设计的话，需要确保能有6位用于表示短操作码，2^x>6，得到3位，
2^x=8可表示8个指令，即多预留了2位可以用于表示长码的前缀。
剩下的8位小概率长码，假设就只取14位指令不再扩展，那么可有式子 (2^3-6) \* 2^y ≥ 8，得到 y=2，即再扩展2bit表示位。

计算其平均码长，结果已经非常接近霍夫曼编码，带来的好处是：码长的种类降低为两种，3位和5位。硬件设计复杂度降低。

## CPU功能与结构

DB(Data Bus，数据总线)，AB(Address Bus，地址总线)，CB(Control Bus，控制总线)
 ![](./COA/Pasted_image_20250325215803.png)

DR(数据寄存器)和AR(地址寄存器)是双端寄存器，一头连接CPU内部总线，另一头连接CPU外部的系统总线。
并且AR是单项的双端寄存器，即CPU内部的地址寄存器只能写不能读，而系统总线对于地址寄存器只能读不能写。

控制器CU会读取IR的指令，对其中操作码进行译码，即IR对CU会有写信号。
PSW对CU也有写信号，比如PSW中存储着转移指令是否执行的判断结果，
如CU收到信号则继续进行PC相对寻址，对PC寄存器内容进行操作。
且控制器有严格的时间先后顺序，所以第三路对CU的输入就是 **时序产生器**。

时序产生器得到的输入是一个时钟信号，它的频率一般称为CPU的主频。

## 指令周期

一条指令从取指令到指令执行结束所用时间称为 (Instruction Cycle) 指令周期。
指令还可以再继续细分，被分为的子周期统称为 **CPU周期** 或 **机器周期**，
这些子周期有三种： **Fetch Cycle** (取指令子周期)、**Execute Cycle** (执行指令子周期)、**Interrupt Cycle** (中断子周期)。

![](./COA/Pasted_image_20250325224736.png)

![](./COA/Pasted_image_20250325225718.png)

子周期中每个微操作称为一个 **节拍**，一个微操作所用的时间也成为节拍周期。

T1：AR ← PC 微操作
	PC out , AR in 微命令
T2：DR ← MEM(AR) 微操作
	AR out, MEMR 微命令
	DR s in (系统总线写入DR) 微命令
地址寄存器写信号把地址给到系统总线，控制器 CU 给一个 MEMR (内存读信号)，
此时主存将选中地址中的数据去除放在系统总线的 Data Bus 上，
CU 给 系统总线 Data Bus 对于 DR寄存器 的写信号，那么就可以把数据读到 DR寄存器。
T3：IR ← DR 微命令
	DR out, IR in 微命令
将取到 DR 寄存器的数据写入到 IR 指令寄存器

以上3个节拍(T\*3)就是CPU取指令到执行一个周期流程。

![](./COA/Pasted_image_20250325224819.png)

![](./COA/Pasted_image_20250325225034.png)

微操作是CPU内最小的动作单位，即节拍周期，
而时钟周期一般用于控制器CU的时序控制，
所以时钟周期和节拍周期在时间层面上应该是并排的。
CPU周期排第三，最慢的应是指令周期。

**现代计算机首选水平型微指令**。

- **水平型**：像汇编语言（如`ADD R1, R2; MOV R3, [R4]`），直接对应硬件操作。

##### 水平型微指令控制域的编码

###### **直接表示法**
微指令控制域中每一个二进制位直接对应一个信号，
需要执行的微操作节拍对应位直接高电平，无需操作的刚好低电平，也就无需译码器了

相容和互斥信号之前有提及，即微操作执行的时间序列上需要遵循的原则。

但是随着通用寄存器数量的上升，控制域需要的二进制位需求更多，
设计起来更复杂，而且高电平位很可能并不多，效率不高。
如果是8个通用寄存器，那么则需要44个直接表示位。

44个直接表示位是怎么来的
> 寄存器选择
	8个寄存器表示位2^3，3位，且直接表示法每个寄存器单独使能。
	CPU读寄存器时有2个端口，1个写寄存器有一个写端口，即3个端口写法，3 \* 8 = 24。
   ALU控制信号
	**ALU 操作**​(如 ADD, SUB, AND, OR 等) 通常需要 ​**4~6 位**​ (取决于支持的运算数量)。
	**ALU 输入选择**​ (是否使用立即数、寄存器等) 可能需要额外 ​**2~3 位**。即，ALU操作和输入需要8位
   内存访问控制
	**MemRead**​内存读 1 位，​**MemWrite**​内存写 1 位，​**地址选择**​（是否用 PC、寄存器等）需要 ​**2 位**。​**总计** ​**4 位**。
   内存访问控制
	**PC 更新**​（是否跳转、自增等）需要 ​**2~3 位**。
   其他控制信号
	**标志位更新**​（如 ZF, CF, OF）1~2 位，​**多路选择器（MUX）控制** 2~3 位，​**总线控制** 1~2 位，**总计** ​**5 位**。
   24(**寄存器读写**) + 8(​**ALU 控制**) + 4(**内存访问**) + 3(**PC 控制**) + 5(​**其他控制**) = 44

#### CPI

CPI (Clock cycles per Instruction)：每条指令执行所用的时钟数。
IPC：每时钟周期执行的指令数。IPC是CPI的倒数。

![](./COA/Pasted_image_20250331150425.png)

有三方面因素使程序的CPI可能不同于CPU执行的CPI：
Cache的行为变化：举例，比如SUB的间接寻址指令访问两次主存，如果Cache命中，那么只会访问1次内存，在该情况下Cache的行为变化明显会影响CPI。
指令混合发生变化：举例，比如流水线中Instruction2需要前一条Instruction1的执行结果来运算，那么在Instruction1完成计算走出流水线之前，Instruction2只能等着。
分支预测发生变化：举例，比如流水线中的跳转判断Instruction执行时，还未走出流水线，那么无法得知是否跳转，为了保证正确不出差，则在跳转判断完成走出流水线前什么都不做自然是最稳妥的。但这会空耗性能，因此CPU会在流水线上预测跳转判断走向，将预测走向的指令装进流水线，但如果后续发现预测错误，那么流水线中已执行的预测指令就需要退回还原，这也会消耗性能。无疑，分支预测发生变化也会影响CPI。(解决方法，加一个分支预测缓存即可。比如循环分支中，将跳转内容装入缓存，每次发生跳转直接在该缓存中取指令即可)

**注意：时钟频率与CPI无关，CPI只是计算时钟周期数，而时钟频率设计到了详细时间，即，CPI 是纯粹的周期数比率，与时钟频率无关。**

#### 指令流水线策略

如果想提高指令流水线的性能，有如下途径：
- 增加指令流水线深度，即任务细分的更深
- 增加指令流水线条数，即引入超标量结构

#### 增加指令流水线深度

- 采用深度指令流水线结构：
  将指令的执行过程进一步细化，
  使流水线的级(段)数变多，而每一级的工作更少、更合理。
- 这样做的两个好处：
  - 流水线**级数**变多、处理更趋合理，
    可使单条指令流水线并行执行指令的能力更强；
  - 每一级的处理**时间**更短，可以进一步提高处理器的工作频率。
- 深度指令流水线可以使处理器执行指令的**速度**更快、**效率**更高。

![](./COA/Pasted_image_20250412191615.png)

之所以CPU发展到后期缺选择缩少流水线的段数，参考下图进行说明

![](./COA/Pasted_image_20250412191728.png)

CPU在指令流水线中进行条件跳转时，会做分支预测，对猜测可能会发生的结果进行预测**并提前执行对应的代码**，
但是如果预测失败，那么要撤销作废掉之前已经执行过的预测指令，同时需要清空整个指令流水线，
再返回之前所在的分支位置，执行已经确定跳转的正确的结果，再去执行对应的指令，
**在分支预测失败时，指令流水线的性能损耗是非常大的，**
**而且指令流水线的级数越高，折损的性能就越大，因此随着CPU的发展，指令流水线的技术又渐渐的减少回十来级了。**

即，并非指令流水线的级数越高越好。
就像Pentium Prescott的主频相比同时期的CPU很高，但实际用起来性能也一般，高频低能。

##### Pentium Prescott流水线流程

下图中的标示写错了，微指令定序器中应该是SRAM，而非SROM
![](./COA/Pasted_image_20250412205926.png)

##### Seg1

段1：以一个块(32Bytes)为单位读取指令Cache

##### Seg2

段2：负责找到指令边界，因为Intel_x86机器指令长度不固定

##### Seg3

段3：动态分支预测器的实现，需要CPU内部有分支预测缓存，
即当前条件转移指令执行过，那么当时是否跳转会在缓存中记录，
如果这条条件转移指令被再次执行，那么动态分支预测器查找缓存，
根据当前分支预测缓存中的跳转次数再次预测，提高预测准确性。
>此处为了简化问题说是需要CPU内部有分支预测缓存，
>专业点来说，动态分支预测器的实现需要依赖​**​分支历史表（BHT）​**​和​**​分支目标缓冲区（BTB）​**​两类关键硬件结构。

##### Seg4

译码部分分为两个段，
段4：指令译码负责把指令负责为简单的微操作(微码，即简单的RISC指令)，

##### Seg5

段5：其中的这些译码器，根据传来的指令会翻译成几条微操作的复杂度，交给对应的译码器处理。
微指令定序器中的RAM中会存有复杂微操作的指令对应的机器码，现代CPU中此处为SRAM。
现在操作系统更新对微指令定序器中SRAM进行写入修改SRAM，来实现和避免指令的漏洞。

##### Seg6

段6：指令译码的第二个段负责按照原始顺序对微操作进行排序，
如果遇到了分支预测指令，此处还有第二条静态分支预测。
它会在一定范围内分析相邻的微操作判断条件转移指令的目的，
如果是为了循环，那么跳转可能性大，如果是错误处理，可能性小，那么猜它不跳转。
接着静态分支预测把预测结果传输给动态分支预测器，
最后根据分支预测的结果确定是否要修改下一条指令指针的内容。

##### Seg7

段7：经过译码两个段，把译码内容送到寄存器分配器RAT，该寄存器功能为寄存器重命名。

```asmmebly
;I6
R1 = R0 - R2
;I7
R3 = R3 * R1
;I8
R1 = R4 + R4
```
以上三条指令之间是互相存在依赖关系的，I6运算结果是I7的计算数，
那么对于R1寄存器来说这两条指令存在先写后读相关，即I6、I7无法在流水线中连续流动，
必须等到I6执行完结果存到R1中，I7才能进行。
I6、I7存在写写相关，I7、I8存在先读后写相关。
因此这几条指令必须顺序执行，不能乱序执行。

**故而可以通过寄存器重命名的方式来减少这几条指令之间的依赖关系：**
**而Intel_x86处理器中有40个隐藏寄存器**，这些隐藏寄存器可以为寄存器重命名使用

```asmmebly
;I6
S1 = R0 - R2
;I7
R3 = R3 * S1
;I8
S2 = R4 + R4
; R1在I6、I7中命名为S1，在I8中命名为S2
```

即寄存器分配器RAT分析指令依赖性并采用寄存器重命名技术。
在寄存器重命名之后指令失去了依赖关系，指令就可以乱序在流水线中流动了。

![](./COA/Pasted_image_20250412213537.png)

##### Seg8

段8：寄存器重命名之后的微操作会**顺序**存入重排序缓冲器ROB中，
它最多能保存40个RISC指令，包括40个隐藏寄存器也存在于重排序缓冲器ROB中。

##### Seg9

段9：保存站DIS在重排序缓冲器ROB(指令池)中找满足条件的微指令，
如果某条微指令执行所需要的数据已经形成了，且其执行需要的硬件资源也已准备就绪，
那么就把该微指令**乱序**取出来通过端口分配到对应的执行单元进行执行。
因为是乱序的，所以可以充分利用硬件资源。
当执行单元执行完对应的指令之后，就会把指令送回重排序缓冲器ROB(指令池)中。
> 段9中之所以执行完再把它放回指令池中，等回收移除之后才写入结果是因为，
> 分支预测未得到结果时，可能预测失败需要作废已经执行的指令，因此需要等退出单元确认没有依赖关系后才写入。


##### Seg10

段10：退出单元在重排序缓冲器ROB(指令池)中寻找**已经执行完毕且没有任何依赖关系**的微操作，
退出单元将该类微操作从指令池中进行回收(移除)，此时它执行的结果才会真正写回程序员可见的寄存器/存储器中。

## 流水线性能度量

### 吞吐率

吞吐率：单位时间内流水线所完成的**任务数**或**输出结果的数量**。
注意理想情况下的最大吞吐率和实际吞吐率是**不同**的，实际吞吐率会稍微比最大吞吐率小。

#### 最大吞吐率

最大吞吐率TPmax：流水线在**达到稳定状态后**所得到的吞吐率。
- 假设流水线各段运行时间**相等**，为1个时钟周期Tclk，则TPmax=1/Tclk，即**流水线周期的倒数就是最大吞吐率**。
- 假设流水线各段运行时间**不等**，第i段时间为τi，则TPmax = 1/max{τi} = 1/τ，**τ就是所有任务段周期时间最长的**。

##### 异步控制分析

下图中 7、8、9 时钟周期的 S3 段 的 I2 指令任务，在执行结束后会把 I2 指令的运算结果给 S4 段，I2走到 S4 段的 第 10、11 周期，
此时 10、11 周期的 S3 段是空闲的，S3 段才可以继续从向下执行 I3 指令，这个 I3 指令是从 7、8 周期 的 S2 送上来的，
即在 7、8、9 周期 S3 段 的 I2 执行期间，7周期 S2 段的 I3 指令是无法送上 S3 的，会覆盖正在执行的 I2 指令，
因此，在 7、8、9周期 S3 段的 I2 执行结束之前，S2 段的 I3 只能等待 S3 段 I2 执行结束，
7、8周期 S1 段的 I4 也只能等 I3 传递当前运算结果后才能继续进行，故而也只能继续等待，一切都是再等高段的 S3 释放，
10、11周期 S1 的 I5 之所以不从 第 9 周期开始，是因为此时 S1 的 I4 还未将 计算结果传递给 S2 段，
如果10、11周期 S1 的 I5 之所以不从 第 9 周期开始，就会覆盖还未传递计算结果的 I4 任务，大家都在等 7、8、9周期 S3段 的 I2 送入 S4段 后 S3段的释放。

在此逻辑基础上，之后进入异步流水线的任务都是以该方式在时空图中排列，等待最长任务周期的S3，

**任务段理想最快为9个时钟周期，而S3段最长需要等待3个时钟周期，所以加起来就是12个时钟周期，即一条指令需要12个时钟周期。**

##### 结论

虽然异步时钟开始完成第一条指令的速度快，

## 流水线指令相关

**流水线的基本性能问题**
限制指令流水线性能提高的因素：
- 流水线的**深度**受限于流水线的延迟、流水线段的时间不均衡和流水线的额外开销。
- 指令执行时可能存在的**相关**(dependence)或**冒险**(hazard)问题。

**相关**：相邻或相近的两条指令因存在**某种关联**，后一条指令不能在源指定的时钟周期开始执行。

**相关**和**冒险**有3类：
- **结构**(structural)相关：资源冲突
- **数据**(data)相关：一条指令需要用到前面某条指令的结果
- **控制**(control)相关：分支等转移类指令/其他能够改变PC值的指令
其中**结构和数据相关**属于**局部性相关**，而**控制相关**属于**全局性相关**，**控制性相关产生时会由于预测失败导致流水线整个清空**。

### 结构相关

![](COA/Pasted%20image%2020250420215522.png)

增加资源副本是解决结构相关最有效的手段，其他方法效果没有该方法明显。

假设要从内存中取数据，而取指令也是从内存中取，
某个时刻，在取I3指令的数据，与此同时取指令在取指令I4，
如果操作数和指令都在内存中，但单端口内存无法同时响应，
这**两个段无法并行工作**，**资源冲突造成流水线停顿**，即产生了**结构相关**，只能先来后到。

最好的处理方法就是增加**资源副本**，即哈佛结构。
做两个主存，一个主存存指令，一个主存存数据。
**且CPU外部有两套独立总线，可以同时访问主存，此时两个段不再冲突**。
**但是因为CPU外部需要有两套独立总线，导致与存储相关的总线电路设计变得复杂，
故现代计算机采用折中方法，CPU外仍采用冯诺依曼结构，
但CPU内部采用哈佛结构，如Cache缓存分数据和指令Cache**。

Intel处理器中一级数据Cache和指令Cache容量为32KB，并采用8路组相联，
那么查一级Cache时，无需等待虚拟地址转换为物理地址，而是直接用虚拟地址查一级Cache。
如果一级Cache容量比较小，且采用8路组相联，刚好可以解决虚拟地址查Cache的别名问题。

如果虚拟地址转为物理地址要使用加法器，且执行指令也需要使用加法器，
为了解决资源冲突问题，可以设计为2两个ALU算术逻辑单元同时工作来解决该问题。

 ### 数据相关

相关类型：
- 先写后读 (RAW, **R**ead **A**fter **W**rite)
- 先读后写 (WAR, **W**rite **A**fter **R**ead)
- 写 - 写 (WAW, **W**rite **A**fter **W**rite)
**先读后写 和 写写 数据相关 都是 异步流水线带来的问题**。

I1-I2，I1在向R0寄存器写入数据结果的时候在第4个时钟周期，而I2读取R0寄存器数据的时候在第3个时钟周期，
I2进入流水线时RD读取数据操作比 I1 快，导致I1还未写入数据时，就用一个还没来的数据进行计算，这造成了RAW。

I3-I4，在向某地址写入数据时需要读取R0寄存器的数据，由于I3是个复杂指令，最后通过R0寄存器数据写入数据时已经是第8时钟周期了，
而I4指令在第5时钟周期就已经对R0寄存器写入数据了，即在I3指令利用R0数据写入之前，I4已经对R0进行修改，这造成了WAR。

I5-I6，I5、I6都是计算指令，即都需要存结果，而二者都需要把数据写入R0寄存器，
依照时间顺序和预定的编程逻辑上来讲，应该是I5写入数据后，I6再写入数据，
但是由于I5是个乘法指令，比I6加法指令复杂，导致该写入数据的操作在流水线上比I6还慢，
故而I6刚写入数据到R0寄存器，下一个时钟周期10时，上一条指令的I5计算结果又跑过来覆盖R0寄存器数据，造成了WW。

![](COA/Pasted%20image%2020250420235129.png)

无论是在顺序流水线还是乱序流水线中，RAW(先写后读)相关都必须优先解决，
顺序流水线中，WAW(写写)、WAR(先读后写)不用解决。在乱序流水线中，WAW、WAR需要解决。

### 处理相关

以下是不同类型指令集处理相关问题的常见手段
- 采用**直通**(forwarding)**技术**(相关直接通路)将运算结果经**相关直接通路**直接送入所需部件。
- 增加**专用硬件**(**推后法**)
  增加流水线互锁(pipeline interlock)硬件。互锁硬件先要检测流水线中指令的数据相关性，当互锁硬件发现数据相关时，使流水线工作**停顿**下来，直到相关消失为止。
- 利用**编译器**
  流水线调度/指令调度：编译器可以对指令重新排序或插入空操作指令，使得加载任何冲突数据的操作被延迟，但对程序逻辑或输出不受影响。

#### 推后法

![](COA/Pasted%20image%2020250421001316.png)

要解决I1-I2的先写后读相关问题，可以增加流水线互锁硬件，该硬件可以判断指令之间的相关问题，
如果产生相关，那么硬件停顿流水线，通过时钟周期的延后已解决相关问题之后，流水线再继续执行。
但这种推后延缓的方法会产生流水线气泡影响性能，仅仅只是保证了运算结果不出错，从性能损失的角度上讲性价比不高。

RISC精简指令集常以MIPS处理器为例，
MIPS在解决相关问题时通常使用软件解决。
精简指令集设计理念是软件能做硬件绝不做，硬件设计要简单。

即**利用编译程序**在一定的范围内搜索不相关的两条指令，或者利用寄存器重命名技术将其相关性消除，
将这两条指令插入到 两条相关的 指令中间，从而拖延第二条相关指令进入流水线的时钟周期，当它进入流水线时相关性已经消失。

#### 冻结流水线

在分支预测出结果之前冻结流水线，等预测结果出来之后再送入任务。
但是冻结流水线的方法相当保守，是早期CPU的处理方法，及其影响性能。

#### 预取分支目标

Prefetch Branch Target(预取分支目标)
在分支预测未得到结果前，提前将分支预测可能要用的指令先提前取来，以此尽可能的节约一点时间。
一般会把提前取来的指令放在特定的缓冲区或缓存中，通常会放在 **L1(I-Cache)指令缓存** 中，
其他的一些设计会放在别的地方，如Intel某些处理器会放在BTB(Branch Target Buffer, BTB)中，命中BTB后将预取指令放入流水线前端。
在支持微指令（μOP）的处理器（如 x86）中，预取的指令可能被解码为微操作并存入 ​**​μOP Cache​**​。
某些高性能处理器（如超标量架构）会直接将预取指令推入流水线前端的寄存器（如 ​**​Fetch Buffer​**​），等待分支结果确认。预测错误要清空流水线。

#### 多流

Multiple Streams(多流)
不跳转或跳转的指令也是提前取来，但是先不送入流水线，
即**同时跟踪和预取多个独立的指令或数据流​**​，以掩盖内存访问延迟，旨在提高处理器的指令供应带宽。
它与分支目标预取（依赖预测）互补，共同优化处理器前端效率。在 GPU、DSP 和现代多核 CPU 中均有广泛应用。

#### 循环缓冲器

Loop Buffer(循环缓冲器)
**将短循环程序整个装入指令缓冲器中**，并暂停指令预取操作，
减少不必要的访存次数，同时让流水时的循环出口恒选猜测循环分支。

以上四种方法都是老式CPU的方式。现在有了大容量的Cache，这四个方法都不是问题。

#### 分支预测

Branch Prediction (分支预测)

##### 静态分支预测

Static Branch Prediction (静态分支预测)
可以采用的预测方法：
- 预测分支之不会发生(Predict never taken)，"出错检测处理"
- 预测分支总是发生(Predict always taken)，"循环"
- 由编译器预测
- 测试法(Profiling)
  实际运行该程序(一般是在模拟器上)，然后将有关信息送给编译器
RISC指令集设计指令格式时，会预置一些位，专门用于存储编译程序在分析时的分支跳转跳转猜测结果，
将猜测结果写入该指令的机器码中，CPU硬件在执行该指令时就会判断预测位，从而得知编译器的预测情况。
那么硬件在执行该指令时，将指令往下一个段中来送时，此时就从跳转的目标地址来去下一条指令往流水线中送。

如编译器判断某条指令为 "出错检测处理"，会有限选择预测不出错的可能性大，
如 "p = fopen(...)" 打开某个文件，会返回一个指针赋值给变量 p，
判断 p 变量中存的指针是否是空指针，则可以确认到该文件是否存在。
那么编译器会对这条指令的预测跳转位标记为 **跳转不发生**，则顺序取下一条指令执行即可。

##### 无条件转移例

###### 延迟转移技术

![](COA/Pasted%20image%2020250421231603.png)

以RISC精简指令集的MIPS为例。
RISC会把不存在相关问题的指令放在分支跳转之前，跳转命令之后，
这很明显从逻辑上存在问题，因为跳转命令先执行，
那么跳转后很明显就**不会再执行穿插在这之间的无相关问题指令**了。
穿插在分支跳转之前，跳转命令之后的这段指令位置称为 **延迟槽**。
RISC硬件上**规定延迟槽中的指令必须执行完才能继续执行后面的跳转指令**，于是问题解决。
在执行延迟槽的无相关性问题指令时，等待分支跳转的判断结果，
从而达成延迟分支的目的，在不断流的情况下完成分支预测。

### Tomasulo算法

Tomasulo算法，也称公共数据总线算法。

IMB360/91被称为是里程碑式计算机，其中的很多设计思想，
如数据表及、寄存器重命名、内存访问冲突的动态检测，
于是就以Tomasulo的名字命名，有了Tomasulo算法。

如下图中要执行的指令仍是包含三种数据相关的一组指令
直通技术建立通道在如此复杂的硬件中，
很明显难以实现，故而该浮点执行部件采用总线来实现直接技术。

![](COA/Pasted%20image%2020250424201704.png)

上图中**第一步**先从主存数据段元A提前取数据放在先行读数栈，当指令需要A单元数据时，将先行读数栈A的数据移至运算单元前的**保留站**，
**第二步**也如法炮制，从通用寄存器F2取来数据存入**保留站**，此时运算需要的两个操作数已经备齐，而**2级流水线的加法器运算需要2个时钟周期**，
所以k+2时刻指令**此时还得不到**用k+1时刻指令运算结果**用做操作数**，于是**第三步**将当前**运算数所在的保留栈站号写入F1寄存器的站号位**，
**同时将F1寄存器的忙位置1，即该寄存器此时无法被读**，用于表示该数据的运算结果还未运算完成，且运算结果处于保留站站号为10的栈中。

![](COA/Pasted%20image%2020250424203236.png)

k+2时刻开始执行乘法指令，**第一步**，F3寄存器数据传入乘除法器前的保留站**第8站**，
再取读取F1寄存器，发现该寄存器处于忙位无法读取，再次读取F1寄存器的站号10，
**第二步**，发现要等待的数据处于保留站10号，而**当前运算的结果恰巧也要写入F1寄存器**，
**于是将当前乘法运算参数所在的保留站站号 8，与 F1 寄存器所等待的计算结果所在的站号 10 进行对换**，
现在F1寄存器的忙位仍是1，等待的是8号位保留站的数据写入，即乘法运算的结果，
而8号保留站的站号位变成了10号站，即8号保留站等待10号站计算结果作为乘法运算的另一个参数，
**第三步**，加法运算两个时钟周期结束后，加法器得出运算结果，将数据传给需要10号站运算结果的数据单元，
通过总线信号，发现乘除法器的8号保留站需要10号站计算结果，于是将结果传入，
无需再向F1寄存器写入该结果，因为刚才对调了所需结果的站号，F1现在需要的是8号站的结果，即乘法结果。

![](COA/Pasted%20image%2020250424210752.png)

6级流水线的乘法器得出结果需要6个时钟周期，因此下个时钟周期执行F1寄存器乘法结果写入主存B数据单元**无法执行**，且F1忙位为1。
**第一步**，于是将当前F1所等待的结果来源，即站号8写给**后写数据站**，此时CPU只能等待或者空转，亦或者接着去执行无相关性的指令，
等6个时钟周期的乘法运算得出结果后，即保留站8号的参数得出运算结果了，通过CDB总线寻找需要8号站数据的数据单元，
**第二步**，将数据同时写入后行写数栈、F1寄存器，同时修改F1寄存器的忙位为0，可以对该寄存器进行读写。等到主存B数据单元空闲时，后写写数栈写入计算结果。

通过每条流水线输入端设置多组保留站来缓存多对操作数，这样可以实现流水线的异步(乱序)流动、解决相关问题、提高性能。

## 流水线的中断处理

- 主要任务：如何处理好**断点现场**的**保护**和**恢复**，而不是缩短流水线的断流时间。
- 方法：
  - "不精确断点法"。如：IBM 360/91
    缺点：不利于程序的设计和排错。
  - "精确断点法"。如：Amdahl 470/V6
    需设置很多**后援寄存器**，以保证流水线内容各条指令的原有现场都能保存和恢复。

对于外设中断，因为外设接口的速度比CPU慢，等流水线排空之后再响应，CPU从时间上根本感觉不到。故采用不精确断点法是可以的。

在下图的情况中，就需要精确断点法了。

## 多发射处理器

CPU内部有多条指令流水线可以同时工作，
即两条没有相关的指令放入俩条指令流水线**并行执行**，这就是多发射处理器。

### 超标量结构处理器

发射是指把某一条指令送到指令流水线中处理，送的过程称为发射。**多条指令可以同时工作的CPU称为超标量结构**。

- **超标量：Superscalar**
- 为了充分利用**度**为**m**的超标量处理器，m条指令必须是**可并行执行**的，否则流水线停顿。
  **度 即 CPU有几条指令流水线可以同时工作**。
- 超标量处理器芯片含有**多个独立的执行单元**，每个单元采用**流水**结构。
- 采用**乱序发射**、**重命名**技术。
- 每指令时钟数CPI实际低于1，通常IPC=2~6。
  引入超标量结构后CPI可以低于1了，一般采用IPC这个单位，
  如**IPC=2即平均每个时钟周期处理2条指令，此时CPI=0.5，即CPI和IPC互为倒数**。

时钟周期3：LOAD "L=M-K" 指令的操作数 M 进内存，K结果还未计算得出无法LOAD，
同时 "K=I+J" 指令的操作数准备就绪，FADD 执行加法 "I+J"，上一个时钟周期2的FADD 执行加法 "A+B"计算完毕，并STORE存入主存C单元。
时钟周期4：上一个时钟周期3的 FADD 执行加法 "I+J"计算完毕，并STORE存入主存K单元。且K操作数已经在内存中，
FADD 直接执行加法 "M + (-K)"，同时 "Q=C×K" 指令的操作数已经准备就绪，FMUL执行 "C×K"。
时钟周期5：上一个时钟周期4的 FADD 执行加法 "L=M + (-K)" 计算完毕，并STORE存入主存L单元。
时钟周期6：上2个时钟周期4的 FMUL 执行**复杂乘法指令** "Q=C×K" **经过2个时钟周期**计算完毕，并STORE存入主存Q单元。

#### 特点

1. **采用显式并行指令计算（EPIC）方式**
    - 程序以二维指令矩阵形式运行，每行指令（超长指令）包含多个无数据相关、控制相关和功能部件冲突的操作，可同时执行。
    - 区别于超标量和超流水线处理机的隐式并行指令（一维线性指令序列，每条指令通常仅含一个操作）。
2. **指令级并行度高**
    - 并行度显著高于超标量和超流水线处理机（后者通常为2，不超过4），当前VLIW处理机可达4至8，甚至几十。
    - 通过并行编译器开发指令级并行性，可在循环、函数或整个程序中寻找并行性，并采用软件流水、循环展开等高并行度方法。
3. **硬件结构规整、简单**
    - 由规则的寄存器、存储器、运算部件和数据通路构成，控制器简单，无需复杂的指令调度窗口或多发射机制。
4. **编译器实现难度大**
    - 依赖指令级并行算法、数据相关性分析、寄存器分配等技术显式开发并行性，需高并行度编译算法，研制难度高。

## 流水线安全问题

### Branch Prediction and Speculative Execution

提高指令流水线性能的手段：**Branch Prediction** and **Speculative Execution** ( 分支预测 和 推测执行 )

-- 为了提高性能，现代处理器采用的技术：
- 分支预测、推测执行
- 乱序执行
- 数据预取
-- 带来的好处：
- 解决了控制相关问题
- 提高了指令流水线的性能
- 也可能会带来一些问题

### 最基本的安全目标

- 保证**用户程序**不能任意访问**内核**/**其他用户程序**的**内存**
- 实现：
  - 操作系统：
    通过**虚拟内存**为每个**应用程序**和**内核**开辟独立的地址空间，规定相应的**访问权限**。
  - CPU：
    通过硬件支持**虚拟存储管理**及其相应的**访问权限**。硬件支持如MMU(**存储管理单元**)

### 安全问题

如果指令3在执行时产生了异常，比如它要访问的内存数据单元处于操作系统内核或其他程序，
当前执行指令所属的程序是**没有权限访问**该数据单元的数据的，因此产生异常，
则异常处理、中断处理程序应该属于操作系统的一部分，会跳转到操作系统内核代码去执行处理该问题。

![](COA/Pasted%20image%2020250426000450.png)

而若该CPU支持乱序执行、数据预取，在执行引起异常的指令3的时候就，
已经根据指令4的要求从主存中将所需数据装载到了Cache中，
从程序的逻辑角度来讲，如果指令3产生异常，
那么指令4肯定是执行不到的，但是CPU采用乱序执行和数据预取，
指令3产生异常的同时，指令4所需数据已经在Cache中，

![](COA/Pasted%20image%2020250426000414.png)

这种方式可以会被黑客利用，产生一定的安全隐患，
比如指令4刚好需要的是系统内核或其他程序的数据，本没有权限访问，
而因乱序执行和数据预取，这**部分数据却在没有权限检查的情况下**被提前装载进了Cache，
等这条指令真正执行的时候，它便不再需要访问主存了，直接从Cache中读取。

此时硬件才会去检测数据是否权限合法，如果合法才会装入对应的寄存器进行计算执行。
即**预取数据不做权限检测，执行时再检查**。所以第4条指令执行时是得不到这些非法数据并执行的。
如果说可以访问Cache中的数据，那么是可以达到攻击的目的的，但是目前没有资料提及可以读取Cache数据，
只有CPU知道如何去访问Cache中的数据，一旦通过主存去获取对应Cache的数据，就会在真正执行时触发权限检测。

虽然从宏观角度来看，结果上程序无法获取到非法数据执行执行，
但是很明显硬件上产生了漏洞：**可以读取任意内存数据到CPU Cache中**。

![](COA/Pasted%20image%2020250426002048.png)

直接读取CPU Cache中的数据目前没有资料，
不过可以通过**边信道**的方式读取CPU的缓存。

#### Side Channel Attack

Side Channel Attack, SCA(**边信道攻击**，又称**侧信道攻击**)
针对加密电子设备在运行过程中的**时间消耗**、**功率消耗**或**电磁辐射**之类的侧信道信息泄露而对加密设备进行攻击的方法。
这类新型攻击的有效性远高于密码分析的数学方法，因此给密码设计带来了严重的威胁。

可以通过**电磁辐射**来猜Cache中的数据，
以买西瓜为例，没买之前没有权限来切开西瓜，
为了确认西瓜的瓤是否熟了，可以通过拍击西瓜来听声音辨别成熟与否。

#### Meltdonw Attack

Metldown Attack (**熔断攻击**)，
通过乱序执行和数据预取执行的攻击称为熔断攻击。

下图中数组中的 data 为系统内核的非法数据的**逻辑地址**，即实施攻击前需要知道非法数据的位置。

![](COA/Pasted%20image%2020250426154710.png)

因为实施攻击需要知道非法数据的位置，但是用户所能得到的只能是数据的逻辑地址，如何获取非法数据地址，
实际上，无论Windows、Linux，每个进程都共享同一个内核空间，因此通过逻辑地址是可以访问到处于高地址的OS部分数据的。

![](COA/Pasted%20image%2020250426160640.png)

大多数CPU预取数据的时候不会跨越域的边界，
而在攻击程序设计的时候可以使数组每个元素之间相隔4K (即一页)，
故而执行当前预取非法数据的程序指令时，取来数据的每个元素就不在同一页，
此时就可以通过边信道攻击精确读到Cache各页的数据内容，分别为数组的各个元素。

以主存Data中的内容作为行号，对应那一行的数据元素，
已经被CPU从主存存到了Cache中，并且数组其他元素没有在Cache中。

假设攻击程序只读取非法数据，而不使用其他数据，那么就可以很显然的判断到预取数据在Cache中的位置。
CPU有提供程序读取时间戳计数器的指令，在每次预取数据前和预取数据后来读取该时间戳，
并对两个时间戳做差值即可得到预取数据需要多久，以此可以判断预取数据所花的时钟周期。

![](COA/Pasted%20image%2020250426154944.png)

256行Cache，每行为一页4K，上图中通过计算预取数据所用的时钟周期来判断哪页的数据是预取来的，
哪页用的周期短就是哪一页，很明显在大约80-90页中有一个节点预取数据所用的时钟周期数极短，这一页存了非法数据。

#### Spectre Attact

Spectre Attact (**幽灵攻击**) 利用 **分支预测** 和 **推测执行** 进行攻击。

用户执行程序时免不了要调用操作系统提供的API程序，或者实现一些中断，
因此必须把内核地址空间映射到应用程序的虚拟地址空间的某个范围内以提高访问便捷性。

在攻击前利用现代高性能处理器提供的Cache操作指令清空Arrary2数组对应的Cache块数据单元，以此提高预取数据的准确性。
接着清空Arrary1数组对应的Cache块数据单元，确保预取该部分数据时花费很长的时间，
此时给x赋非值，如比array1_size的 **16** 大，如把 **高位内存数据单元逻辑地址 - array1首地址 的 值 赋值给 x**。
很明显x的值因为过大无法执行if语句块内的内容，但CPU执行if语句时会先做if判断，且之前已经清空了判断值所在的Cache，
这个时间CPU要几百个时钟周期去主存中读取数据与x值作比较，这几百个时钟周期在进行时，
CPU为了提高性能就会开始分支预测，如之前这个指令执行过，猜测该分支会进入并执行，CPU就会提前执行下面的语句。
故而推测执行直接抢跑执行预取，直接读取`array1[x]`，且**推测执行认为内核后面会处理下标越界的问题**，
最终推测执行直接读取到指定非法数据地址的内容作为数组的下标，将该数据存入Cache中，非法的数据在未经权限检测的情况下被获取。

之后，只要通过不停地向后遍历后续的非法地址，就能把所有的非法数据全部存入Cache中进行窃取。

![](COA/Pasted%20image%2020250426164746.png)

很显然x在array1中是会发生数组越界的，但是`array1[x]`会完成非法数据的预取，之后就和熔断的攻击手法一样了。
幽灵攻击可以无视权限读取任意内存地址空间的非法数据，无论是内核数据还是其他用户程序的敏感数据都是可以读取的，如账号密码等等。

#### 解决办法

地址布局随机化，包括内核地址随机化和进程堆栈地址随机化。
- 使得攻击难度变大：入侵者不知道哪个内存地址包含敏感数据，没办法一举就把系统攻破。
- 只能延缓或者降低攻破可能性。
把内核地址映射表和用户地址映射表分开。

# 总线与输入输出系统

总线
- 类型、结构
- 信息传输方式
- 总线仲裁
- 典型的总线
Bus (总线)，是计算机系统的**互联机构**，连接两个或多个总线设备的**公共通信线路**，
是一组有定义的、可**共享**的、可传递0、1逻辑信号的**连接线**，通常分为**地址**总线、**数据**总线、**控制**总线。
总线设备分为：**Master (主设备)、Slave (从属设备)**，
主动发出地址信号、读或写的控制信号的设备就是主设备，反之是从设备。
且主设备需要使用地址总线来选择从设备，在通过控制信号线来与从设备进行信息交换。

输入输出接口

输入输出技术
- 程序查询
- 中断
- DMA (直接存储器存取)
- I/O通道 (只有在大型计算机有)
- 操作系统的支持

![](COA/Pasted%20image%2020250427212447.png)

任何两个模块都是有专线的，并行效率非常高，此方式称为**全连接**，
但是随着模块数的上升，电路设计会越来越复杂。
故而实际设计的时候可以采用最简单的公共数据通路。
其中传输地址的信息的称为地址信号线，控制读写信号的称为读写信号线，
传输数据的称为数据线，并且所有的线都连接在公共的数据通路上，
且总线还需要分时使用，即在两个模块互传数据的时候，其他模块不能使用总线。
在模块数不多的情况下，使用分时总线带来的性能损失也是完全可以接受的。
在模块非常多的情况下，各个节点之间不会再使用分时总线，而是采用"互联网络"的方式连接。

## 总线类型与结构

### 总线类型

按**连接层次**分类：
- 片内总线：芯片内的总线，如单总线结构、双总线结构、三总线结构。
- 系统总线：电路板内部用于连接芯片与芯片之间、模块与模块之间、电路板与电路板之间的总线。
  举例：如**PCIE**总线，一般用于连接两块电路板。如组装高图形处理能力的主机，
  就要将显卡插到主板的**PCIE**扩展插槽上；且现代微处理器CPU内部其实也会设计有**PCIE**总线，
  如CPU内核、高速缓存、控制器、高速接口等之间互联，它们之间也很多设计采用**PCIE**总线连接。
- 通信总线： 比如通过USB总线(接口)连接打印机到计算机系统。
依照与CPU的"**距离远近**"进行排序：片内总线离CPU最近，接着是系统总线，最后是通信总线离CPU最远，用于连接计算机外设。

![](COA/Pasted%20image%2020250427215502.png)

主存需要控制器才能接到总线上，其他外设也都需要控制器/接口来接入总线，
随着计算机的发展，人们把**高速接口**统一设计在一起作为**北桥**，**低速接口**设计在一起作为**南桥**，
之后集成度越来越高，大部分现代计算机将北桥取消，一并设计进CPU内部，来提高主存访问速度，只保留了**南桥**。

系统总线、通信总线通常都是由各大厂商共同商店的"**标准化**"总线。

按**数据位数**分类：
- 并行总线
  总线数据线如果由多根，如8、16、32，它就是并行总线，一次可以传输多个二进制位。
- 串行总线
  总线数据线如果只有一根，那么它就是串行总线，串行总线一次只能传输一个二进制位。
按**用法**分类：
- 专用总线：只连接一对功能部件，可以提高性能。
- 公用(共享)总线

## 总线的信息传输方式

### 总线操作

![](COA/Pasted%20image%2020250427223708.png)

PCI属于同步总线，所有的动作需要与时钟信号同步，因此PCI总线中会有一条时钟信号线。
PCI支持 **多主控**，即任何设备连接到PCI总线上都可以成为主控设备，
但在成为主控设备之前会有一个**仲裁**的过程，最终胜利的那一个设备才会成为主控设备。
假设某一台设备已经成为了主控设备，由该设备来**控制总线**，通过总线进行数据传输，
FRAME上带横杠表示低电平有效的信号，此时主设备将FRAME信号置为低电平，
以此通知总线其他设备主设备要与某台从设备进行通讯，从设备提前做好准备，
将相应的地址放在32**根**的**AD**线上，AD线地址线和数据线复用的。
与此同时，AD下的四根线，如C/BE给总线命令0110 (**主存读**，如下图)。
因为从设备里面的寄存器通常会映射到内存地址空间中，故而主设备向总线发出了内存读的命令。

PCI总线命令 (地址节拍)
![](COA/Pasted%20image%2020250427223757.png)

当其他从设备读取到总线的读命令之后，从设备会检测该映射的内存地址空间是否在自己的管辖范围内，
如果不在范围内则不处理，如果在且确认到读命令，那么该从设备就会被选中，则需要把**从设备被选中DEVSEL置为低电平**通知主设备。
主设备知道从设备存在之后，接着主设备**准备**从从设备读相应的设备，而**不是立刻**，**主设备需要等待一个时钟周期**，称为**总线转换周期**。
因为主设备发的是一个读命令，此时AD这32根线对于主设备来说是一个**输出**，
在进行数据传输时，数据由从设备提供，从主设备来讲AD这32根线又是一个**输入**，
为了**避免总线竞争**，于是AD在使用时需要一个**总线转换周期**，使得主设备把地址信号从AD线上撤掉，这样从设备才能把数据放在AD上。 

在总线转后周期后，只要从设备处于准备好的信号状态(TRDY)、主设备也处于准备好的信号状态(IRDY)，
那么从设备在每一个时钟周期的**上升沿**就能传输一个数据。
理想状态下主设备在AD上只传输一次地址，总线转换周期之后，从设备一直传输数据。
如果主设备想要结束数据传输，只需要将FRAME置为高电平，再传输完最后一个数据后传输结束。

这种数据传输方式就是**突发读写**，只需要传输一次地址还有命令，只要主从设备同时处于就绪状态，
后面每一个时钟信号的上升沿就可以读取一个数据，在数据量很大的情况下，前面传输地址和命令的时间几乎可以忽略不计。

设某CPU主频为33MHz，AD线32根，**每个时钟周期的上升沿传输一次数据**，故一个时钟周期数据一次可以传输32bit(4B)，
PCI理想情况下的带宽，突发读写每个时钟周期可以传输4Bytes，主频33MHz，每秒可以33M次数据传输，则 4Bytes/S * 33M = 132MB/S。

### 数据传输方式

总线上进行一次传输的过程：
- 传输请求
- 总线仲裁
- 部件/设备寻址
- 数据传输
- 总线释放
总线一次传输的过程像是法庭上发言的过程，确定好发言人再发言，
发言的时候其他人不说话，发言完毕后向其他人通知可以发言，即释放总线。

数据传输的基本方式：
- 并行传输方式：传输速率高、需要较多的数据线，不适合远距离传输
- 串行传输方式：只用一条数据线，传输距离远
并行传送在高频传输的情况下会出现很多难以解决的问题，如线间干扰问题、时钟偏移问题、时钟同步问题。
因为串行的总线一次只传输一个数据，故而没有以上的问题，如再使用差分传输数据，时钟频率也可以提高。
这样串行的数据传输效率也可以比并行的传输方式高，还解决了疑难杂症，现代计算机大部分设计都逐渐向串行过度。

![](COA/Pasted%20image%2020250427235626.png)

- 分时传输方式：在**不同时段**利用总线上**同个信号线**传送**不同信号**。减少总线线数，提高总线的利用率。
前面提到的PCI中的AD线，地址和数据线复用的情况，这就属于分时传输方式，不同时间段传输不同类型的数据。
- 消息传输方式：(消息：一种规定格式的数据包，该数据包可以包含地址、数据或控制等信息)。PCI、USB、......
即传输数据的时候会依照一定的格式标准，如以太网数据传输以一帧一帧为准进行数据传输，后面再跟循环冗余校验码、帧结束标志等。

## 总线通信方式

### 同步通信方式

优点：速度快，接口逻辑简单。
缺点：
- 总线上的每个设备必须以**相同的时钟频率**运行，且时钟速率依**慢速设备**而定；
- 时钟偏移 (clock skew) 问题：
  **总线时钟频率 ↑** ==> **总线长度 ↓**

### 异步通信方式

- **无时钟信号线**
- 使用握手协议 (handshaking protocol)
  非互锁、半互锁、全互锁
  串行异步通信：不用握手信号、无时钟信号
不同速度的设备就可以采用异步通信方式，不用统一设备之间的步调。
其中的握手协议就相当于，高速设备与低速设备之间的协调，即高速设备等低速设备将数据处理好再一起继续工作。

#### 发送设备发起的异步通信

异步通讯设备之间应有**数据线**、(处理握手协议的)**握手线**。
其中握手线应分为 **Data-Ready(就绪线)、Acknowledge(确认接收线)**。
如果总线挂接多个设备则还需要**地址线**，此处为简化问题，选择两个设备单独连接总线。

![](COA/Pasted%20image%2020250505215600.png)

首先发送设备将数据放在数据线上，并在**Data-Ready线**上给高电平告诉接收设备数据准备就绪，等接收设备准备好并且接收到数据后，
接收设备向**Acknowledge线**给高电平告诉发送设备接收成功，此时发生设备就可以把数据线上的数据撤掉，发送下一组数据。
如果接收设备确认接受数据后，Acknowledge线置高电平且还未来得及更改为低电平，
发送设备此时发送第二组数据时可能会认为已经接受完了发送第三组数据，在这种情况下的数据传输是不可靠的。
故而在**全互锁**的方式下，该问题可以得到有效解决。发送设备检测数据应答的时候，会等接收设备对Acknowledge线的一次低电平信号，
即一组高低电平视为一次完整的数据传输，在没有确认到Acknowledge的低电平时，发送设备认为一次数据还未接受完，选择继续等待。

#### 接收设备发起的异步通信

![](COA/Pasted%20image%2020250505222533.png)

首先接收设备请求数据需要将**Data-Request线**置高电平，发送设备检测到请求后将数据放在数据线上，
接着发送设备将**Acknowledge线**置高电平告诉接收设备数据线上数据已经准备就绪，等对方来取，
此时接收设备即可采样Data线取走数据，并将**Data-Request线**置低电平，结束数据请求，
发送设备一旦确认到**Data-Request线**低电平，就把第一个数据从数据线上撤走，并把**Acknowledge线**应答信号置为低电平。
同理接收设备也必须等发送设备将**Acknowledge线**置为低电平之后，才能发送第二次的数据请求在 Data-Request 线上。

传统串行接口是RS-232，计算机内的第一个串行接口是COM1、第二个COM2......
![](COA/b2b34cd6-e1ae-4443-98fa-54d4edaa22c4.png)
如Windows设备管理器中能看见COM，其中就要提前约定好波特率每秒传输多少个数据位，一次接收几位(默认8bit)，要不要奇偶校验位等等。
如上图数据线起始是高电平，如果置为低电平则代表起始位，数据开始传输，根据预先的设定，每隔多久对数据线上的数据进行一次采样读取。
校验位确认数据完整后，读取到停止位则结束本次数据传输。作为串行异步通信，如一次传输1Bytes数据，那么再传下**一个数据也需要从新的起始位开始**。

虽然说串行异步通信没有时钟信号，但是两边的波特率约定的是相同的，只要传输数据完整即可，每隔固定时间采样数据线数据。
## 总线的仲裁

- 主方：启动一个总线周期
  从方：响应主方的请求
- 多处理器系统
  各**CPU模块**的总线请求原则：**公平**
  **I/O模块**的总线请求：优先级
  速度慢的设备优先级低点，速度快的高，
  这样低速设备等待时间于自己来说可能还没什么感觉。
- **Bus Arbitrartion (总线仲裁)**：
  用来决定哪个主设备可以使用总线的**选择机制**。
- 按照总线仲裁电路位置不同，仲裁方式可分为：
  **集中式仲裁**：有专门的独立硬件做仲裁，即仲裁器。
  - 链式查询方式 (菊花链)
  - 计数器定时查询方式 (轮询)
  - 独立请求方式
  **分布式仲裁**：总线竞争中各设备自带优先级标识，通过并行比较自主决定总线控制权，无需中央仲裁器，实现高效自治的仲裁方式。
  如：SCSI总线

### 集中式仲裁

#### 链式查询(菊花链)

总线仲裁器应有 **Bus Grant (仲裁线)、Bus Request (请求线)、Bus Busy (忙线)**
其中每个设备都应该有一个输出引脚：**总线请求、总线忙**，对于总线仲裁器都有**总线允许信号**。
**下图BR、BB以低电平有效为例，即BB接收到低电平视为占用、BR接收到低电平视为有设备申请仲裁成为总设备**。

实际上集电极开路、漏极开路还是有上拉电阻和+5V电源的，图中为简化问题没有画上。

![](COA/Pasted%20image%2020250506195234.png)

但是上图中的所有设备都是将输出引脚一起接在**同一条**BR、BB总线上的，这很明显会出现总线竞争问题。详细描述如下：

![](COA/Pasted%20image%2020250506181708.png)

OC门输出(**集电极开路**)引脚是可以接在一起的，
通常外部需要一个上拉电阻，通常再接到+5V电源上。
当所有的输出引脚都输出高电平时，接在一起的引脚才会输出高电平，
如果有一个低电平，那么无论如何都会输出低电平。由此实现**线与逻辑**，且**不会产生总线竞争**。

仲裁器还要检查忙信号，如果当前某一个设备正在使用总线，那么它会把总线忙信号给有效电平位，这种情况下仲裁器不会分配总线。
如BB是高电平不忙，且存在请求信号低电平有效，此时仲裁器检测到后就会开始分配总线，将 **Bus Grant 总线允许信号置为高电平输出**，
设备读取到 Bus Grant 总线允许信号后，确认自己是否需要仲裁，如果确认，则**将 Bus Busy 忙线置 低电平有效位，此时即可取得总线使用权**。
如果当前不是需要总线的设备，则将得到的 **Bus Grant 总线允许信号** 向后面的设备传输，直到传到需要总线的设备，至此**不再向后传输**。

故离仲裁器最近的设备优先级是最高的，且该优先级于软件层面无法更改。
但硬件上将新设备接入链中即可，有着可扩充性。
同时接线不多也简单，不存在硬件过于复杂的问题，成本低且容易实现。
缺点是灵活度较差，因为优先级是固定的无法改变，哪个设备离仲裁器最近哪个设备优先级高。
且可靠性也存在问题，如链中的某个设备如果出现故障，
那么就无法再从此处向后传递  **Bus Grant 总线允许信号**，之后的设备就无法再得到总线的使用权了。

#### 计数器定时查询(轮询)

实际上集电极开路、漏极开路还是有上拉电阻和+5V电源的，图中为简化问题没有画上。
如有8个设备，且每个设备需要有编号，那么轮询技术中的线路只需要三条以3bit表示即可 (2^3=8)。

![](COA/Pasted%20image%2020250506204913.png)

上图仍以BR、BB低电平有效为例，如第二个设备和最后一个设备同时申请总线，将BR置低电平。
若忙线BB是高电平，那么仲裁器将轮询技术线置000，开始问0号设备是否申请了总线，
此时0号设备对BR是高电平，即没有申请，故对该轮询不做任何回应，仲裁器得不到回应，
接着仲裁器继续向下轮询询问，将轮询技术更改为001，而第二个设备001正是申请总线的设备，
于是001置BB忙线为低电平，仲裁线发现BB忙线低电平有效，将总线分配给001，并不在向后轮询询问，

可靠性比菊花链高，比如一个设备坏了，也仅仅是轮询时没有任何回应，不影响其他设备的回应。
且仲裁器可以自己决定优先级，完全看仲裁器从几号设备开始询问。
但是轮询技术的扩充性不是很好，如果扩充设备轮询技术的线数需要增加，
总线分配速度也会比较慢，比如最后一个设备才轮询得到总线的使用权。

#### 独立请求

相当于每个设备与仲裁器之间有专线了。

![](COA/Pasted%20image%2020250506210652.png)

优先级可以改变，由仲裁器决定。
总线分配速度也快，因为每个设备都是专线连接。
可靠性也高，一个设备有问题也不影响其他设备。
缺点是电路复杂性高，线数多，成本高，可扩充性差。

### 分布式仲裁

分布式即没有仲裁器了

#### 自举分布式

![](COA/Pasted%20image%2020250506211445.png)

如果有n个设备，那么就有n个BR总线请求线，越靠前的设备优先级越高。
以D3设备获取总线为例，首先需要确认BR1或BR2电平是否有效，如果有效，则说明D1或D2设备正在使用总线，
此时D3设备等待优先级高于自己的D1或D2设备，等BR线无效且BB线无线，D3设备再发送BR3有效电平，同时置BB线有效电平，得到总线。

#### 链式分布式

设备仍然是链式连在一起，**Bus Grant (仲裁线)** 的信号仍需要通过优先级高的设备向后传递。
**Bus Grant (仲裁线)** 接了一个VCC一直有效，相当于设备可以随时来取总线，无需仲裁器存在。

![](COA/Pasted%20image%2020250506212146.png)

哪个设备需要则自己将BR、BB置有效位，等两个线置无效位完全释放总线后，其他设备才可以依照先后顺序的优先级来使用总线。

## 典型的总线

通常CPU是总线上的主设备，谁是主设备谁就在主线上发送地址和读写控制信号。
一些比较高级的总线也支持多主控设备，挂接在总线上的设备都有可能成为主控设备。

### 常见总线

典型的系统总线 (内总线)
- ISA总线 (**Industry Standard Architecture** 工业标准体系)
  已经被淘汰，但是该总线设计比较简单，以此为例容易理解总线。
- **PCI总线** (**Peripheral Component Interconnect​**​ 外围组件互连)、PCI Express (PCIe)总线
  随着时代发展，现在计算机内的总线已经是PCIE总线了，
  (CPU)片内的总线也不一定是标准总线，而是商家自己设计的。
  且PCIE使用差分传输，支持全双工，可以同时端到端点到点进行数据收发。
  计算机主板上会有一个根节点的PCIE总线，现代计算机(**把北桥**)设计进了微处理器中，称之为主桥。
  主桥会产生若干个PCIE总线的口，每个总线接口都可以连接设备，
  如接口不够，接口可以接集线器，然后其他设备再连集线器，比较类似树型网络结构。
  PCIE对于传统的PCI总线**从软件上讲**是向下兼容的，如将总线接口寄存器的地址映射到内存中，软件访问这些地址的方式是统一的。
  同时软件上还支持多通道方式，两个设备相联的总线如只有一对输入输出，则称`PCIE*1`，
  如显卡通过`PCIE*16`的插槽连接到计算机的主板上，即16个通道是可以同时工作的，多通道还可以提高PCIE的带宽。
典型的通信总线 (外总线)，用于连接计算机系统和外设之间的总线
- RS-232C
  计算机中传统的串行接口就是RS-232C ，该接口因大体积已经淘汰了，
  但是该类型的硬件资源与主板上还是存在的，如COM接口。
  不过该接口即使波特率调整到最大速度也并不是很快，故现在用于调试硬件而非传输数据。
  同时该线实现简单，仅需要TxD、RxD、GND三根线即可，如单片机的开发在线调试。
  现在计算机没有RS232接口，不过单片机开发时是会用USB转RS232的转接口来完成该操作。
- **USB**
  USB总线，基于USB​ (**​Universal Serial Bus​**​ 通用串行总线) 协议的物理层面的连接器。
- SCSI
- SAS
  SCSI是并行接口，SAS是串行接口。
  SCSI、SAS协议也用于连接机械硬盘，
  一般用于服务器或工作站，即高端的存储设备高端的硬盘。
- NVME
  固态硬盘专门的传输协议，底层再借助PCIE总线传输数据，
  高端固态硬盘不会采用SATA协议，采用SATA协议的固态硬盘仅仅是为了安装方便。
- ATA
- SATA
  SATA的S是串行的S，即 **Serial**，现代设备大多数采用SATA协议进行串行连接，
  早期ATA是并行接口，一般用于连接机械硬盘，后来出现了串行接口，即SATA接口。
  ATA本身也是一个协议，机械硬盘也是通过ATA协议的物理层接口连接到主板上的。
  因为并行接口在高频下很难提高速度，如时钟同步、线与线之间的电磁干扰等难以解决，故用串行提高速度。

USB：**U**niversal **S**erial **B**us，通用串行总线。

- VBUS (电源)
  可以实现总线供电，故有5V电源和底线，即可以通过USB接口为外设供电，但有一点的限制，5V电源只能提供500MA(**毫安**)的电流。
- GND (地)
- D+ (信号正端)
- D- (信号负端)
  用于传输数据、控制信号的就是D+、D-两根线，显然这个串行总线是通过这两根差分的线传输数据、信号的。

三种传输速：
- High-Speed (高速)，传输位速率为 480Mb/s
- Full-Speed (全速)，传输位速率为 12Mb/s
- Low-Speed (低速)，传输速率为 1.5Mb/s
此处传输速率单位中的b是bit，而不是字节Bytes。

#### USB3.0

USB3.0多采用一对SSTX线来传输数据，故而**USB3.0可以在全双工模式下工作**，
在接收数据的同时可以发送数据，在发送数据的同时可以接收数据，传输速率可以乘以二倍。

其中 Super-Speed 5.0Gbps 转换为以 Bytes 为单位的 GBps 时，**换算不能直接除以 8 ，而是需要除以 10**，

导致​ **​20%的带宽损失​**，即除以​10综合了单位换算和**编码开销**。
如PCIe 1.0/2.0、SATA等使用8b/10b编码的接口，均需按此方式计算有效带宽。

## I/O接口

从软件角度触发，控制外设最终就是对接口中的寄存器进行读写。

![](COA/Pasted%20image%2020250508211250.png)

如果想了解接口情况，可以读取接口中状态寄存器的数据。
而对接口做某些操作时，就需要向控制寄存器发送控制信号。
如果向接口对应的设备传输数据，软件将数据写入数据寄存器，再由接口写入设备。

由于涉及寄存器，故存在接口寄存器的编码地址，而I/O地址有两种方式：
- 存储器映射方式 (统一编址方式)
  将主存与I/O设备放置在**同一个地址空间中**，如RISC处理器。
  I/O设备与主存使用相同的**指令**和**控制信号**。
  不需要专门的I/O指令，可以**简化控制**。
  在地址空间确定的情况下，两者的**地址扩充**相互制约。
  Motorola 680X0 系列采用此方式。
- I/O映射方式 (独立编址方式)
  主存与I/O设备使用各自**独立**的**地址空间**，如CISC x86。
  要求系统提供专门的**I/O指令**。
  对主存与I/O设备采用不同的**读/写控制信号**。
  便于系统**调试**与**维护**，便于主存与I/O**地址空间**的**扩展**。
  I/O设备的操作**不够灵活**。
  Intel微处理器采用此方式。

### Tech Talk

现代计算机RISC和CISC已经逐渐有着相互融合的趋势了，
如 现代 CISC x86 内核已经是 RISC 结构，
将内存取来的复杂CISC指令，
通过译码器翻译成若干条简单的 RISC 指令再交给 RISC 内核处理。
但是 CISC 为了向下兼容仍然保留了 in / out 指令，没有彻底摒弃独立编址。

从8086开始接口最大的寻址空间就是64KB，但现代仍然是64KB，
之所以没有扩大，是因为现在的新软件已经不用in、out指令的接口地址空间了，
独立编址访问地址空间很单一，灵活度很差，性能也会出现问题，
故**新接口新外设的接口存储空间都是直接把地址映射到主存，采用统一编址方式**。

PCI总线为了兼容老设备、软件，接口地址空间还需要保留，
但PCI总线只占用两个接口地址，还是相当节省的，对其中的寄存器初始化后，
就可以它内部大量的存储器映射到主存，之后用访问内存的指令就可以访问到PCI接口的设备。

如 32 位Windows操作系统最大有 4G 的寻址空间 (2^32 = 4GB)，
接入 4GB 内存条，但是进入系统发现只有3.25GB，
这是因为需要提前预留主存地址空间来映射各种外设的接口，用于控制外设。
故而在内存条大于等于4GB时，安装的操作系统一定要64位，从而提高主存容量。

## 输入输出技术

选择 I/O 技术的基本原则：
- 能满足用户的**数据传输速度**要求且不丢失数据
  即使取走数据避免后续数据将其覆盖
- **系统开销尽量小**
- 能充分发挥**硬件资源**的能力 (使**I/O设备**与**CPU**尽可能**并行**工作)

### 常见IO方式介绍

|​**​方式​**​|​**​CPU 参与度​**​|​**​适用场景​**​|​**​核心缺点​**​|
|---|---|---|---|
|​**​程序查询​**​|100% 保姆式参与|教学演示、古董设备|CPU 沦为"状态检查工具人"|
|​**​中断驱动​**​|响应式参与|键盘、鼠标等低速设备|高频中断时上下文切换开销大|
|​**​DMA​**​|仅初始化|硬盘、网卡等高速设备|总线带宽竞争|
|​**​I/O 通道​**​|只发宏观指令|企业存储、GPU 计算|硬件成本高，设计复杂|

#### 程序查询方式 (Programmed I/O)

- ​**​比喻​**​：CPU 像个老妈子，挨个敲门问外设：“你有事吗？没事？那我过会儿再来问！”
- ​**​原理​**​：
    - CPU 主动轮询 (Polling) 每个外设的状态寄存器，检查是否有数据需要处理。
    - 硬件简单，但 ​**​CPU 全程打工​**​，效率极低 (比如读硬盘时，CPU 99% 时间在空等)。
- ​**​缺点​**​：
    - ​**​CPU 浪费​**​：外设慢悠悠干活，CPU 却得不停查岗。
    - ​**​无法处理紧急事件​**​：如网卡突然收到数据包，但 CPU 还在查键盘状态。


#### ​中断驱动方式 (Interrupt-driven I/O)

- ​**​比喻​**​：外设装了“呼叫铃”，有事就按铃喊 CPU：“别刷剧了！快来帮我！”
- ​**​原理​**​：
    - 外设准备好数据后，通过中断信号 ​**​主动通知 CPU​**​。
    - CPU ​**​保存当前工作现场​**​ (保护断点)，转去处理中断服务程序 (ISR)，完事后恢复原任务。
    - ​**​支持优先级​**​：高优先级中断可以打断低优先级中断 (比如硬盘报错 > 鼠标移动)，可以层层进行 "中断嵌套"。
- ​**​优点​**​：
    - CPU 不用轮询，​**​解放算力​**​去干别的。
- ​**​缺点​**​：
    - ​**​频繁中断仍有开销​**​ (保存/恢复现场、切换上下文) 。
    - 高速设备 (如 SSD) 可能让 CPU ​**​疲于应付​**​ (中断风暴)。

#### DMA 方式 (Direct Memory Access)​

- ​**​比喻​**​：CPU 雇了个“搬家工 DMA”，指挥它：“把这堆数据从硬盘搬到内存，搬完叫我！”
- ​**​原理​**​：
    - ​**​DMA 控制器​**​ (DMAC) 直接接管总线，​**​绕过 CPU​**​ 在内存和外设间搬运数据。
    - CPU 只需初始化 DMA (告诉它搬哪、搬多少) ，然后忙自己的事。
    - 搬运完成后，DMA 发个中断通知 CPU 收尾。
- ​**​优点​**​：
    - ​**​CPU 零参与搬运​**​，效率飙升 (尤其适合大批量数据传输，如视频流、磁盘读写) 。
- ​**​缺点​**​：
    - ​**​总线竞争​**​：DMA 和 CPU 抢总线可能引发瓶颈 (现代系统有优化) 。

#### I/O 通道方式 (I/O Channel)​​

- ​**​比喻​**​：CPU 是老板，通道是部门经理：“张经理，硬盘那摊事交给你了，月底给我报表就行！”
- ​**​原理​**​：
    - ​**​通道是专用协处理器​**​，能独立管理外设 (比如硬盘控制器、显卡的 Command Processor) 。
    - CPU 只需下发任务 (如“读取文件” )，通道自动执行 ​**​完整 I/O 操作​**​ (寻道、传输、校验) 。
    - 比 DMA 更高级：DMA 只管搬数据，通道还能处理 ​**​设备管理、错误恢复​**​ 等复杂逻辑。
- ​**​应用场景​**​：
    - 高端存储 (RAID 控制器) 、GPU 计算任务卸载。

### 程序查询方式

![](COA/Pasted%20image%2020250511220917.png)

CPU循环读取设备的状态寄存器直到确认设备不忙，不忙时再进行I/O操作。
如果CPU传输完一轮数据后还有第二轮数据传输，而设备因速度问题仍在接收第一轮数据，则CPU只能等待，没有精力处理其他程序。

![](COA/Pasted%20image%2020250512145301.png)

```assembly
; 初始化数据段和指针
; 确定数据存储的位置（BUFFER），DS:SI 指向缓冲区的起始地址
MOV AX, SEG BUFFER ; 获取缓冲区BUFFER的段地址 
MOV DS, AX ; 存入DS寄存器（数据段基址） 
MOV SI, OFFSET BUFFER ; 设置SI为缓冲区的偏移地址（指针）

; 设置循环次数
; 表示CPU需要从外设读取1000个数据，存入缓冲区
MOV CX, 1000          ; 设置循环次数1000（读取1000个数据）

; 查询外设状态（BUSY信号）
; 7DH端口​​是​​状态端口​​，BUSY信号在D7位（最高位）
RE: IN AL, 7DH ; 从端口7DH读取状态（BUSY信号在D7位） 
SHR AL, 1 ; 右移1位，将D7移入CF（进位标志） 
; 将D7位移入CF（Carry Flag），若CF=1（BUSY=1），说明外设忙，CPU继续轮询
JC RE ; 如果CF=1（BUSY=1），继续等待

; 读取数据并存入缓冲区
IN AL, 7CH ; 从端口7CH读取数据 
MOV [SI], AL ; 存入缓冲区（DS:SI指向的位置） 
NC SI ; 指针SI+1，指向下一个存储位置 
LOOP RE ; CX-1，若CX≠0，继续循环
```

### 中断方式

I/O接口的硬件上也需要实现中断功能使之可以向CPU发送中断请求。

![](COA/Pasted%20image%2020250512172615.png)

call指令作为程序员自己写的指令，在执行前会把PC寄存器压入栈中，无需保存PSW。
而中断处理时需要把PC、PSW都压入栈中，因为之前的程序还未执行完，
为了确保后续运算不影响PSW，故而需要保存PSW内容，并且执行完当前正在执行的DEC CX指令后才能进行中断跳转。
跳转到中断处理程序后，还需要保护现场，即通用寄存器，如后续在处理中断服务时要用到 AX、BX、CX 则需要压入栈中。
中断处理程序执行结束后将压入栈的通用寄存器的数据全部恢复(POP)出栈，接着使用`IRET`中断返回读取跳转前程序的位置PC，恢复PSW后继续执行。

其中保护断点PC、PSW入栈是**硬件**来完成，PC和PSW是CPU内的专用寄存器，
保护现场是用中断服务程序的软件来实现的，保护现场保护的寄存器是通用寄存器。

而对于中断处理，每个程序的中断处理内容都不同，故采用软件处理更为合适。

![](COA/Pasted%20image%2020250512181533.png)

#### 中断源的选择与识别

##### 中断判优

当多个中断请求同时发来时，需要对**这些中断请求的优先级进行判别**，优先处理优先级高的中断请求。

![](COA/Pasted%20image%2020250512183709.png)

菊花链式的中断判优基本上与总线仲裁的菊花链一般无二。
设备向INTR请求线发送有效电平信号，则CPU得知至少一个相连设备需要中断，
CPU向离自己最近的设备在INTA响应信号上置有效电平，等待响应，
如设备1不需要中断，就会把信号向与设备1相连的后续设备传递，直到有设备向CPU确认该信号。

分组独立请求，每个分组虽然独立，不过每组内部仍采用的是链式查询。
CPU中会有可编程中断控制器来专门做中断判优，与分组和分组中的链式查询相连。
由优先级仲裁控制器来找出中断请求信号中优先级最高的设备的中断向量码提供给CPU。

### 直接存储器存取方式

Direct Memory Access, DMA - 直接存储器存取方式
Direct Memory Access Controller, DMAC - DMA控制器

大量数据传输让CPU来做过于消耗资源，可以通过以中断的方式用一个专门搬用数据的硬件 DMA 来执行此类任务。

#### DMA工作过程

CPU首先对 DMAC 进行初始化工作，
比如两个接口希望向内存写入数据，就向DMAC发送DMA请求信号，
DMAC向CPU申请总线的使用权，CPU结束当前总线周期后才可以响应DMAC的请求。
> 结束当前总线周期：假设CPU正在访问主存或接口，此时正在读的时候肯定不能释放总线，需要等到当前任务完成后再释放总线，即结束当前总线周期。

下图中的1个指令周期包含5个CPU周期，且本图是在计算机不支持虚拟存储器、Cache等，CPU与其他设备的速度都是一直的理想情况下设计的图。
 ![](COA/Pasted%20image%2020250512211709.png)
 
CPU**结束当前指令周期**后才会去响应中断，CPU结束当前(CPU/总线)周期后才会去响应DMA请求。(针对早期计算机)
CPU结束总线周期后向DMAC发送应答已经释放总线了，此时DMAC再给发送DMA请求的接口应答准备传输数据，
此时DMA成为系统总线的主设备，主设备负责向总线上发送内存地址、还有接口读、内存写等地址，
DMAC把对应的内存地址放在地址线上，同时发出内存写、接口读的控制信号，
**因为DMA请求由接口发出，一旦得到应答允许之后，接口就会默认处于被选中的状态，**
**所以接口在读的时候不需要给接口地址，只需要给接口读的命令信号就会把数据放在数据线上。**
对于内存来说，地址由DMAC给出，同时给了内存写信号，数据线上有接口提供的数据，于是可以把接口读出的数据写入内存指定单元。
传输本次数据后，将需要传送的数据次数减一，如果次数没有减到0，
把内存的下一个地址放在地址线上，再重复之前的操作直至需要的数据传输次数消失。

![](COA/Pasted%20image%2020250512213211.png)

当一批数据数据传输完，即计数值为0时，DMA传输也结束了，
DMAC将对CPU的总线请求置为无效，CPU检测到无效信号后，
CPU再来接管总线，继续再通过主存取指令做一系列操作。

#### DMA工作机制

DMA与CPU是如何切换对总线的控制权的

显然CPU将总线占用时间分配给DMAC使用会减少CPU对内存的访问带宽。
而如果把存储器的存取周期变为原来的两倍，一倍给CPU，一倍给DMAC用，显然主存的带宽变成了原来的一半。
周期 (挪用 / 窃取)，即DMAC先确认CPU是否在使用总线，如果没有使用总线，DMAC迅速的偷偷使用总线进行任务。

##### 周期挪用(窃取)方式

- 两种情况：
  隐藏周期DMA：窃取总线
  暂停CPU方式：抢总线
- 特点：
  当主存工作速度高出外设较多时，可提高主存的利用率，且对CPU的影响较小。
  高速主机系统常采用这种方法。

#### 通道工作过程

![](COA/Pasted%20image%2020250515233026.png)

用户程序运行起来的时候并非直接可以执行，而是需要调用系统的接口程序来执行这个操作，
而管理程序就相当于系统函数程序，由管理程序生成通道程序，一旦通道程序生成，
管理程序最后直接启动通道命令，此时通道即可工作。通道根据用户程序中的事先设置的地址开始执行命令。
此时操作系统的管理程序将取到的数据返回用户程序，此时通道程序和CPU执行的用户程序是并行工作的。
当通道把任务执行完毕后，通道向正在并行处理用户程序的CPU发送中断，
CPU响应中断后进入中断服务程序，在中断处理程序中会记录一些信息，如使用外设的时间长度并计费，
接着CPU中断返回，继续接着执行刚才的用户程序，这就是传统的通道的工作过程。现在大型计算机的通道也已经有了很多的不同。

#### 通道结构与类型

字节多路通道: 最简单、最慢，该通道轮流给多个外设提供服务，且每次只给一个外设提供一个字节的数据。
- 适用于**字符类低速**外围设备，通道的数据宽度为**单字节**，以**字节交叉方式**轮流的为多台外部设备服务。如光电机。
- 字节多路通道包含有多个子通道，每个子通道连接一个设备控制器。
选择通道: 一旦选中某个外设就必须把该外设所要求的数据全部传送完才能给其他外设提供服务。
- 选择通道为优先级高的**高速外围设备**服务，如磁盘。数据传送以成**块**方式进行。
- 每个选择通道只有一个以**成组方式**工作的子通道，逐个为多台高速外围设备服务。
数组多路通道: 前二者的折中，选中某个外设后，可以在没有传输完数据时给其他外设提供服务，且并非一次提供一个字节的数据。
- 数据多路通道：把**字节多路通道**和**选择通道**的特性结合起来。
- 连接多台高速外设，每次为一台高速设备传送一个**数据块**，并轮流为多台外围设备服务。
- 数组多路通道可以被看作是以**成组方式**工作的高速**多路通道**。数据宽度为**定长块**。
- 例：从磁盘存储器读出一个文件的过程：定位、找扇区、读出数据。
- 数组多路通道的实际工作方式是：
  在为一台高速设备传送数据的同时，有多台高速设备可以在定位或者在找扇区。
- 与选择通道相比，数据多路通道的**数据传输率**和**通道的硬件利用**都很**高**，**控制硬件**的**复杂**度也高。

通道最大流量是指单位时间内通道的数据流量带宽。

# 并行体系结构

现在想提高计算机系统性能最常见的办法就是采用并行处理技术，
如引入流水线，流水线称之为指令级的并行，彷佛多条指令在同时处理。
指令流水线到达一定程度之后再想提高性能，就需要引入多核多处理器多线程技术，线程并行。
继续提升性能，如超级计算机由很多节点组成，每一个节点都是一个多喝多处理器的结构，称之为多计算机系统，任务级并行。

## 阵列处理机与向量处理机

SIMD：单指令流、多数据流，可以同时处理多对操作数，同时得到多组结果。其中包含**阵列处理机**与**向量处理机**。

### 阵列处理机

Array Processor (阵列处理机)
一个控制单元有很多处理单元，控制单元从主存取来一条指令，该指令在执行时由控制单元产生相应的控制信号，
让这些处理单元并行工作，每一个处理单元都能处理一对数据得到一对结果，并行工作就能同时处理多对数据得到多对结果。

![](COA/Pasted%20image%2020250517210603.png)

### 向量处理机

Vector Processor (向量处理机)
向量处理机的向量寄存器可以存储数组，这么一个寄存器可以存储64位数据，
如果是64个元素，一个元素包含64位数据，那么整个数组/向量可以存储在向量寄存器，
且向量处理机有很多向量寄存器，且硬件支持向量类型的运算。 向量运算处理多对操作数得到多对结果，显然属于SIMD结构。

![](COA/Pasted%20image%2020250517211654.png)

现在SIMD已经很少了，因为**现在的SISD冯诺依曼机也有很多SIMD向量处理机的特征**，
如 Intel AMD x86 处理器已经引入和很多新的单指令流多数据流结构类型的指令，
单指令流多数据流结构类型的指令称之为**多媒体扩展指令集(MMX)**，
该指令集后续发展升级到**流媒体处理指令集**(**SSE**)，继续发展到**高级向量扩展指令集(AVX)**。
故现在的大多SIMD机器既是标量处理机也是向量处理机，现代计算机中SISD与SIMD的界限已经很模糊了。

## 多处理器系统

MIMD：多指令流、多数据流，多核多处理器系统。

**非一致性存储器访问**的显著**非一致性存储器访问**是**共享内存**。
根据共享内存的不同**实现**方式
- **UMA**多处理器系统：Uniform Memory Access，**一致性存储器访问**计算机。
  **一致性存储器访问**，无论哪个内核哪个处理器访问主存不同单元所花费的时间都一样。
- **NUMA**多处理器系统：Non-Uniform Memory Access，**非一致性存储器访问**计算机。
  **非一致性存储器访问**，同一个内核或处理器访问主存的各个单元所花费的时间可能不同。
- **COMA**多处理器系统：Cache Only Memory Access，基于Cache的存储器访问计算机。
根据共享内存的不同**组织**方式
- **集中式**共享存储器多处理器系统
- **分布式**共享存储器多处理器系统

![](COA/Pasted%20image%2020250517213522.png)

![](COA/Pasted%20image%2020250517214028.png)

如 Intel AMD x86 构成的计算机系统，所有的内核都是一模一样，且功能一致地位一致，
访问所有内存地址花费的时间都一样，这种计算机称之为**对称多处理机系统**，**属于UMA一致性存储器访问计算机的一种**。
不对称的处理机系统如智能手机、平板的ARM芯片，采用大小核设计，
因为是电池供电所以节能第一，性能第二，待机时为了省电小核工作，性能消耗剧烈时大核工作。

如全球500强计算机，Sunway Taihu Light(神威太湖之光)。
多计算机系统的核心问题在于**这么多计算机如何互相协同工作**。

**多计算机系统**：由独立的计算机作为节点、通过高速的互联网络互相连接而构成的系统。
- MPP(**Massively Parallel Processor**，大规模并行处理机)：使用专用通信网络构成。
  例如，IBM的BlueGene/L。
- 机群：由比较简单的非定制组件构成。
  例如，Google的搜索引擎。
**多计算机系统**要解决的主要**问题**：
- **负载平衡**技术
- **可靠性**技术
  如机群就是由普通计算机构成的，如果一个节点出问题，把数据复制到其他的机器上保证可靠性。
  而某一个节点出现了问题，可以把当前出现问题节点所进行的任务迁移到好的节点上，这也属于软件层次上的可靠性技术。
- **并行程序**调试工具：
  并行程序的执行过程不能重现，因为多核处理多线程任务的调试难度非常大，且存在各种条件竞争和随机性，这样就不能复现。

### 大规模并行处理机

MMP: Massively Parallel Processor，大规模并行处理机
设计理念：性能越高越好，多花钱无所谓，一般用于各个国家的政府机构
如IBM生产的超级计算机，放在安全局、能源部、核安全局，或者用来研制新型武器。

特点：
- 大多数MMP系统使用**标准的CPU**作为它们的处理器，常用的有Intel Pentium系列、Sun UltraSPARC和IBM PowerPC。
- MMP系统使用**高性能**的**定制**的**高速互联网络**及网络接口，可以在低延迟和高带宽的条件下传递消息。
- MMP是一种**异步**的**分布式存储器结构**的MIMD系统，它的程序有多个进程，分布在各个微处理器上，每个进程有自己的独立的地址空间，进程之间以**消息传递**进行相互通信。
- 大规模的MPP系统使用特殊的硬件和软件来监控系统，**检测错误**并从错误中平滑地**恢复**。
MMP实例如 IBM Blue Gene 系统

### 机群

一般给公司来用，公司强调的是性价比。
在保证性能的前提下越便宜越好，故而其中的每个节点一般使用的就是个人计算机。
节点与节点之间的连接采用的是现在最流行最便宜的以太网连接。

机群系统 (Cluster): 一组完整的计算机相连，它们作为一个统一的计算机资源一起工作，并能产生一台机器的印象。
- "完整计算机"：意指一台计算机离开机群系统仍能运行自己的任务。
- 结点：机群系统中的每台计算机。
机群是**并行**或**分布**计算机系统的一种类型，它是由一组完整的计算机(结点)通过**高性能的网络**或**局域网**互联而成的系统，它作为一个**独立**的**统一计算资源**来使用。

**机群**与**局域网**：
局域网强调的是资源共享，结点与结点之间不协同工作。
机群强调的是结点与结点之间的协同工作，从用户的角度看不到结点，看到的是一台完整的高性能计算机。

### 网格

网格由许多安装了客户端程序的**志愿者**的个人计算机组成，
这些**自愿加入网格的**个人计算机可以充当结点来为他人提供服务和运算，最后将结果传回核心服务器。
早期的网格客户端程序都是屏幕保护程序，在计算机不使用进入屏幕保护状态时就会充当结点，现在客户端多为后台运行服务。

![](COA/Pasted%20image%2020250517234542.png)

现在个人用的比较多的还是多处理器计算机，而多计算机系统公司和企业用的比较多。
其中多处理器计算机分配资源的最低单位是线程，可以共享内存，编程采用**多线程编程工具**。
多计算机系统因为各个结点之间采用互联网络连接在一起，
互联网络的以太网因为网络延迟较高，所以各个结点之间是不共享内存的，
故而无法采用多线程编程工具，而是**采用 MPI (Message-Passing Interface)，消息传递接口**。

**Cache(一级)的平均访问时间计算公式：Ta = h \* Tc + (1-h) \* (Tc + Tm) = Tc + (1-h) \* Tm**
Ta为平均访问时间，h为命中Cache的概率，Tc访问Cache的时间，
(1-h)为未命中率，Tm为未命中Cache将数据从主存取出装入Cache的时间，Tc是访问Cache的时间

在有二级Cache的情况下，**将 L2 Cache 与 主存 看作一部分**，那么就可以直接套用前面的Cache平均访问时间计算公式了。
